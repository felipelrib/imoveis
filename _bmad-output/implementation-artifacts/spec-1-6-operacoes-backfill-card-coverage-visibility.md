## Intent

**Problem:** The story-1.5 backfill control plane (`/admin/backfill/*`) has no consumer: the operator still drives a multi-day cloud run from a terminal, and nothing anywhere shows how much of the DB is actually enriched. Story 1.4 (the DB-derived coverage endpoint this UI is supposed to read) never landed — it escalated in this same loop run on a stale branch-state blocker and is still `backlog` — so `Cobertura de IA` has no data source at all.

**Approach:** Land the missing FR-29 coverage endpoint (story 1.4's scope, absorbed here because story 1.6 is undeliverable without it) as an auth-gated, purely DB-derived `GET /admin/enrichment/coverage`, then build the UX-contract surfaces on top of it and on 1.5's status route: an Operações backfill card (pt-BR state, budget/throughput/ETA text lines, start/pause/resume, lease-conflict toast, running warning line), a per-signal coverage card, and a Painel health strip carrying a backfill chip and `Cobertura de IA N%` (minimum across signal types). The v0.13 UI default locale flips to pt-BR at the same time.

## Boundaries & Constraints

**Always:** Coverage figures come from SQL over `properties` / `metrics_scoring` — never from the runner's Redis checkpoints (FR-29); Redis is read only to answer "is a run live" and to serve 1.5's existing status route. Fractions are floats in `[0.0, 1.0]` on the wire, typed in `src/api/schemas.py` with `response_model=` on the route and covered by `src/tests/contract/`. Signal-type identity is `EnrichmentTaskClass` (`src/core/enrichment.py`) — no new vocabulary, English on the wire, pt-BR only as a rendered label. Pure coverage/ETA math lives in framework-free `src/core/` and is TDD'd; SQL lives in an adapter; the route stays thin glue (one happy + one degraded path). The route sits on the existing `verify_admin_access` admin router; failures go through `raise_api_error`. Every new string lands in BOTH `en` and `pt-BR` catalogs. Absent data renders absent — no bars, no spinners over content, no fabricated ETA/throughput/percentage (UX-DR3/5/6). New UI uses the Meia-noite tokens from DESIGN.md, minted as CSS custom properties, dark-only. The frontend talks only to the FastAPI surface (AD-8).

**Block If:** Nothing. Story 1.4's acceptance criteria are fully specified in `epics.md` and its escalation cause (an unmerged story-1.3 follow-up branch) no longer exists; this worktree is clean and branched off a `main` that carries 1.5. Sprint-status records the absorption for both keys.

**Never:** Do NOT change the backfill runner, the lease/budget/checkpoint semantics, the pacer, `scripts/dev/backfill_gemma.py`, `migrate-primary.sh`, AI prompts or clients, or any primary-stack docker action. Do NOT add a stop control (start/pause/resume is the sanctioned surface). Do NOT introduce a second telemetry bus, a second quota consumer, or a progress metric sourced from Redis. Do NOT add a "dia N de ~M" day counter (the mockup shows one; no field in the DB or the control plane can honestly produce it). Do NOT touch Epic 2 surfaces (percentile badge, filters, side panel), per-scraper chip semantics (FR-37, v0.14), or the property grid.

## Design Notes

**Why 1.4 is absorbed rather than blocked:** 1.6's ACs consume a coverage API that does not exist; the loop already advanced past 1.4's escalation (whose cause — an unmerged 1.3 follow-up branch — has since landed), so blocking again would stall the epic on a resolved problem. The endpoint is built to 1.4's own acceptance criteria, and sprint-status/feature doc record that 1-4 landed inside this branch.

**Signal set:** the API returns all five `EnrichmentTaskClass` members (1.4's AC says "per Story 1.1 signal type"); the UI renders all five rather than UX-DR6's illustrative four, so no measured signal is hidden. `deal_verdict` renders as `veredito do negócio`, `valuation` as `avaliação estatística`.

**Denominator:** active properties only. Delisted rows are never enriched and would permanently depress coverage and stall the ETA — exactly the dead-completion-branch failure v0.13-fu3 fixed in the runner.

**Absence over zero:** `total == 0` yields `fraction: null`, not `0.0`; a run with unusable history yields `throughput_per_day: null`. The UI renders `null` as an omitted line, never `0%`. Review pass 2 added the third case the lease clamp created: a window shorter than fifteen minutes yields `null` too, because two snapshots thirty seconds apart make a number, not a rate.

**The lease says a run exists, not that it is getting anywhere.** Three review passes each found the same defect behind a different field: a figure gated on liveness when it should have been gated on *work*. The settled division is — `active` (the lease) decides whether a run exists and therefore whether the controls act on anything; `heartbeat_active` decides whether rows are being enriched right now, which is what `migrate-primary.sh` refuses on and so what the warning line states; and the rate and the ETA additionally require the run not to be `paused`, `backing-off` or `blocked`, because the server measures them over a window clamped to the lease and would otherwise keep quoting the pace of a run that has stopped. `idle` is deliberately not in that list: the state key decays on a TTL under a slow row (DW-20), and a live run reads back `idle` while it is very much working. The budget line is gated on the lease alone — today's consumed quota is a fact whatever the runner is doing.

**The locale flip reaches further than chrome:** `ui.locale` is also what `resolve_ai_output_language()` prefers (BIN-101), so flipping the default to pt-BR flips the language new AI free text is written in on any deployment with no Redis `ui:locale` override. That alignment is the designed behaviour for a pt-BR product and the backfill converges the corpus, so it stands — but it is a behaviour change the Code Map above describes as a formatter/chrome change, and it is now stated in the feature doc and above the config key rather than discovered in production.
