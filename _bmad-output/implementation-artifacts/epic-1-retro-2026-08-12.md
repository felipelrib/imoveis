## 2. What went well

### 2.1 Vocabulary-first sequencing was the right foundation call

Story 1.1 shipped the canonical `EnrichmentTaskClass` enum into `src/core/` **before any consumer existed**, and the sequencing gates (`1.2←1.1`, `1.3←1.1`, `1.4←1.1`) held. Across five downstream stories, **no per-feature vocabulary appeared** — routing, backfill scope and coverage telemetry all speak the same words, which was the epic's stated consistency convention.

The review patch that made the routing map **total** (every task class must have an entry) converted a class of latent mid-pipeline `KeyError`s into a startup error, three stories before they could bite.

### 2.2 The review loop caught silent failures, not noisy ones

The highest-value findings were all *invisible-in-production* defects:

- **Story 1.3** — a quota-exhausted call fell back to `condition_score=0.5`, `run_enrichment` persisted it, the checkpoint advanced, and `mode=missing` (keyed on `not score`) permanently retired the row. Silent corpus corruption behind a healthy progress banner.
- **Story 1.6 pass 1** — the ETA, the story's headline number, was averaged over a fixed trailing 24h of snapshots, so a 30-minute-old run had its rate divided across 23.5 idle hours: overstated by more than an order of magnitude.
- **Story 1.6 pass 2** — the always-visible warning line read `não rode validate.sh durante o backfill`. Since `v0.13-fu1`, `validate.sh` is explicitly primary-safe; the one persistent sentence of a six-day run instructed the operator not to run the merge gate.
- **Story 1.5 pass 1** — the `--serve` supervisor consumed the start request *before* validating it could run anything, then died on it: a Start button that silently ate the operator's request.

### 2.3 Test discipline held under pressure

- **Mutation-checking** was applied consistently: stories 1.3, 1.5 and 1.6 each reverted the fix and confirmed *exactly* the new regressions failed, then restored and re-ran green.
- **Coverage theater was actively removed**, not just avoided. Story 1.5 pass 2 deleted a test that passed because of a *comment* on a line, and replaced four docstring-substring assertions with one AST-based structural check. Story 1.6 pass 3 replaced an `assert router.dependencies` auth-gate test that any dependency kept green.
- **Drift-locks were invented where two copies had to stay honest** — the coverage SQL predicate and the runner's own census are pinned against each other across six config shapes.
- **Story 1.3 pass 2** caught that the Lua scripts implementing mutual exclusion and the RPD ceiling had *never executed* — the fakes dispatched on script identity and re-implemented the logic in Python. An integration test now runs them against real Redis.

### 2.4 Deferrals were principled, not evasive

Items explicitly fenced by a story's own intent contract were ledgered rather than scope-crept. DW-17 is the clearest case: closing the fabricated-0.5 hole for non-quota failures was *forbidden* by story 1.3's own "Never" clause because the local Ollama path depends on that fallback. Deferring it was correct; what was missing was scheduling it.

## 3. What didn't go well

### 3.1 Story 1.4 escalated on a blocker that had already cleared

1.4 escalated on 2026-08-06 on a stale branch-state blocker — an unmerged story-1.3 follow-up branch — **which had since landed**. Nothing re-drove it. The loop advanced past it, and 1.6 (whose ACs consume 1.4's endpoint) absorbed the scope.

Consequences:
- **1.6 became a three-story branch**: coverage backend + control UI + the AC-mandated locale flip that rewrote assertions in 17 e2e specs. The spec self-describes as "oversized by design".
- **1.4 sat marked `done` with no feature doc** — a CLAUDE.md non-negotiable — until review pass 3 of a *different story* caught it.

There is no mechanism that re-checks whether an escalation's stated cause is still true.

### 3.2 Review passes converge on defect *families*, not instances

Story 1.6 pass 3 states it explicitly: *"This is the third door into the same defect"* — a figure gated on **liveness** (the lease) where it should have been gated on **work**. Passes 1, 2 and 3 each caught one member of that family (state-decay, heartbeat, then paused-run).

Story 1.3 shows the same shape at larger scale: 4 passes, 64 patches, with pass 4 finding 7 new deferrals rather than converging.

**The insight:** when a third pass finds the same *shape* through a different field, the answer is a spec-level invariant in the I/O matrix, not a fourth pass.

### 3.3 The ledger grew 4.5× faster than it drained

Closed 7, opened 32. Several open items are not small:

| Item | Consequence |
|---|---|
| **DW-17** | Non-quota AI failures (401 revoked key, 404 retired model, DNS outage) still write a fabricated `0.5`, commit, advance the checkpoint and permanently retire the row — ~4,600 properties/day behind a healthy banner. |
| **DW-27** | `POST /admin/backfill/start` only *records* a request. Nothing executes it unless a hand-started `backfill_gemma.py --serve` is alive. No unit is committed or wired into the stack. |
| **DW-18** | The daily budget charges a flat 3 requests/property, but one property is up to 45 real HTTP calls (3 stages × 3 JSON attempts × 5 retries) — and 429s are retried, so the overshoot is worst exactly when the account is already throttled. |
| **DW-11** | After a lost lease, still-draining rows advance the *shared* checkpoint, rewinding the successor's position and inflating `processed_total`. |
| **DW-20 / DW-9 / DW-21** | One missing background ticker, three consequences: the published state decays to `idle` under a live run, the `:active` heartbeat lapses so `migrate-primary.sh` reads idle, and the lease goes unrenewed during candidate fetch/census/inter-pass windows. |

### 3.4 FR-28's stated outcome is unmet at the consumer

FR-28 reads: *"the resumable backfill runner **graduates from `scripts/dev`** to an operator-facing operation."* The control plane shipped and is correct. The thing that *executes* a requested run is still `scripts/dev/backfill_gemma.py`, now required to run continuously. This is DW-27, and it is a topology decision (committed systemd unit vs. dedicated compose service vs. promoting the runner to a supported entrypoint) with the cloud-key placement and residential-IP invariants in play.

CLAUDE.md's rule is *"merged-and-pushed is finished"*. By that rule, roughly half the epic was not finished when this retrospective opened. The bmad-loop finish path merged locally without completing the push.

## 4. Handover to Epic 2 — two inherited surfaces its ACs don't mention

Epic 2 is genuinely independent at the code level (different files, no shared core, gates `2.2←2.1`, `2.3←2.1`, `2.4←2.3`, `2.5←2.2`). But Epic 1 handed it two cross-cutting UI defects:

1. **ToastProvider anchor.** `frontend/src/components/ToastProvider.tsx` is top-right anchored; DESIGN.md's toast spec — binding via **UX-DR3 on every Epic 2 story that surfaces a toast** — is bottom-anchored, max two stacked. Re-anchoring restyles flows every page inherits and needs its own e2e sweep.
2. **pt-BR plural agreement, now the default and pinned.** The 1.6 locale flip promoted pre-existing single-form catalog keys (`"1 selecionados"`, `"1 imóveis"`, `"1 favoritos"`, `"1 quartos"`) from an opt-in preference to *everyone's default* — and 1.6's e2e repairs **asserted them verbatim** in `compare-select.spec.js`, `compare-map-select.spec.js` and `compare-view.spec.js`. Stories 2.2, 2.4 and 2.5 all add pt-BR strings and e2e specs on top of those assertions.

**Also carried forward:** the locale flip reaches past chrome — `ui.locale` is what `resolve_ai_output_language()` prefers (BIN-101), so all new verdict/visual/sentiment free text is now written in Portuguese on any deployment without a Redis `ui:locale` override. This is designed behaviour and the backfill converges the corpus, but Epic 2's percentile copy lands on a corpus mid-transition.

**No epic-plan invalidation found.** Epic 2's stories, ACs and sequencing gates remain sound as written; nothing in Epic 1 proved an Epic 2 assumption wrong. The two items above are additive prep, not a re-plan.

## 9. Key takeaways

1. **Foundation-first sequencing works.** One canonical vocabulary, landed before any consumer, produced zero dialect drift across five stories and one epic.
2. **Reviews find families.** Three passes catching the same defect shape through different fields is a signal to fix the spec, not to run a fourth pass.
3. **Deferral without scheduling is just debt.** Every deferral in this epic was individually correct; the aggregate — 7 closed, 32 opened — was not managed until this retrospective.
4. **"Done" needs a liveness check of its own.** Four follow-up keys, one epic key and nine merges were each individually correct and collectively out of sync with reality. Status is a claim; it needs verification against the tree and the remote.
5. **An epic can meet every acceptance criterion and still not deliver its FR.** FR-28's ACs were all satisfied while its stated outcome — graduating the runner out of `scripts/dev` — was not. AC coverage is not outcome coverage.
