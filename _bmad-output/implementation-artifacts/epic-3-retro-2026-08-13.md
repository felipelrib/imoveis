## 2. What went well

### 2.1 One review pass per story — the epic-1 lesson landed

Epic 1 averaged 2.6 review passes per story (1.3 burned 4 passes / 64 patches). Every Epic 3 spec froze an intent contract and I/O & edge-case matrix up front, and **every story converged in a single review pass with zero intent-gap or bad-spec loopbacks**. This is epic-1 action item **A2** ("promote defect families to spec-level invariants instead of running more passes") visibly working. The two high-severity review findings that did occur (3.1's silent-upgrade `enable --now` no-op; 3.5's preflight certifying a crash-looping host) were both caught *inside* the single pass.

### 2.2 The operator handoff became a defect detector

The `awaiting-operator` → `bmad-loop confirm` flow surfaced four defects no review pass had found, because they only manifest when the runbook is *executed*:

- **DW-31** — story 3.1's own operator instructions prescribed the committed-YAML edit that reddens the merge gate (verified by making the edit: 1 failed, 70 passed).
- **DW-33** — `.env.local` doubling as the unit's `EnvironmentFile=` and the gate's sourced env (observed as an unrelated Redis test failing on a partial routing map).
- **DW-32** — `start.sh` auto-migrates the primary DB, bypassing the fu6 mutual exclusion (high severity, still open).
- **DW-34** — `--status` prints "supervisor: not running" for the entire duration of a supervised run.

Story **3.5 was minted from the first two and delivered inside the same epic**, in parallel with Wave B, exactly as the process intends. The epic absorbed corrective scope without losing its wave discipline.

### 2.3 The wave plan held, and finishing meant finished

3-1 serial → 3-2 ∥ 3-3 ∥ 3-5 → 3-4, no merge races on `src/core/backfill_runner.py`, all merges by the orchestrator, and `origin/main..main == 0` at this retrospective — the exact check epic-1's A4 demanded, after that epic left origin 9 merges behind.

### 2.4 Design decisions were made with evidence, not taste

Story 3.4 rejected the monotonic-CAS option by proving `Property.id` is a random UUID and that *nothing reads `last_property_id` back* — which also exposed that DW-11's stated harm ("re-enrichment of a gap") never existed. Story 3.3 chose aggregate-not-per-row reconciliation from the shared-client topology. Story 3.5 chose the allowlist over a second env file with the rejected alternatives recorded. Each spec carries the trade-off in writing.

## 3. What didn't go well

### 3.1 The operator-handoff flow created real friction (Felipe)

Five separate per-story checklists confirmed in two days, with the same Docker-restart instruction repeated verbatim in three specs, and environment-recovery steps ("start Docker Desktop") mixed in with genuinely privileged actions (sudo installs, live-run verification). The signal was valuable (§2.2); the *packaging* was the problem. → Action item **R1**.

### 3.2 A story's runbook was its own worst defect — and reviews can't see that class

DW-31 shipped through a 17-patch review pass with two independent reviewers. Operator instructions are claims about a host the reviewers cannot execute against; only performing the handoff falsified them. **Decision (Felipe): treat as a one-off, not a new spec-level obligation** — the handoff flow itself is the detector for this class, and it worked.

### 3.3 The ledger grew net-positive for the second consecutive epic

Closed 6, opened 20 (~46 open at close). Every deferral was individually principled — most are explicitly fenced by a story's own intent contract — but epic-1's A5 ("a net-positive epic ends with a scheduled drain wave") was not addressed: no delta was recorded at epic close and no drain wave was scheduled until this retrospective. The epic-1 retro's own candidate bundle (DW-9/20/21, the background-ticker family) is still unscheduled.

### 3.4 Follow-up-review recommendations are falling into an invisible gap

All five Epic 3 specs carry `followup_review_recommended: true` with the damping cap spent — and unlike DW-1/DW-26/DW-30, none has a ledger entry. The recommendation exists only in spec frontmatter nothing sweeps. → Action item **R2**.

### 3.5 The plan of record carried a false premise for a delivered story

epics.md's story 3.4 promised "a lease handover does not cause re-enrichment of a gap already covered" — a benefit the mechanism cannot deliver because the gap never existed (resume is `mode=missing` set subtraction; the checkpoint marker is never read back). The 3.4 spec deferred the correction to this retrospective; it is applied as part of this wrap-up.

## 5. Decisions taken (Felipe, 2026-08-13)

1. **Operator-handoff friction → batch per wave.** One consolidated, deduplicated operator checklist per wave/epic instead of per story; identical actions collapse into one entry with one confirm. (R1)
2. **DW-31's shape is a one-off.** No new spec-level obligation for operator instructions; the handoff flow is the detector for that class.
3. **Mint the corpus repair as Story 2.7, gating 2.1.** Rows stamped with fabricated 0.5 scores *before* story 3.2 landed are permanently outside the candidate set (`mode=missing` keys on `not score`), and Epic 2's percentiles would compute over them — the missing half of the Epic 3 → Epic 2 gate. Owned by Epic 2, same precedent as 2.6.
4. **Correct epics.md story 3.4** as part of this retro's wrap-up (see §3.5).
5. **Drain wave: DW-32 now, ticker bundle later.** DW-32 (high severity — `start.sh` migrates the primary DB with no heartbeat probe, no migration lock) is driven to resolution before Epic 2 Wave 1; the DW-9/20/21 background-ticker bundle is recorded as scheduled after 2.7 rather than minted now. (R3)
6. **Epic-1 items A2/A3/A4 → `done`;** A1 and A5 stay `open` (A5's success criterion now reads against Epic 2's close).

## 10. Key takeaways

1. **Frozen intent contracts + I/O matrices are what single-pass convergence looks like.** The 13→5 review-pass drop is the epic-1 A2 lesson institutionalized, not luck: invariants moved into the spec before implementation, and reviewers verified against them instead of rediscovering them.
2. **Executing the runbook is a verification tier of its own.** Four defects — including the epic's only high-severity pair — were invisible to two independent reviewers and trivially visible to the operator performing the steps. Keep the signal, fix the packaging (R1).
3. **"Done" now survives its own audit.** Origin in sync, every feature doc present, live-verified outcome — the claims epic 1 failed on were all checked and all held this time. The verification habits stuck.
4. **A deferral system needs a drain policy, not just an intake policy.** Two epics running, the ledger is +39 net. The intake discipline is excellent — deferrals are principled, fenced, and well-evidenced — but without a scheduled drain wave per epic (A5, still open), principled deferral is still just debt.
5. **A sequencing gate is only as good as both of its halves.** "Epic 3 before Epic 2 so the corpus is trustworthy" stopped the bleeding (3.2) but did not clean the wound (2.7) — the gate's rationale covered both, the stories covered one. Check a gate's *rationale*, not just its listed stories, before declaring it satisfied.
