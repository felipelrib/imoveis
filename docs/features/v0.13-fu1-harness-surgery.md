# Harness surgery — primary-safe validation + BMad-only, PR-less harness

> Feature branch: `feat/v0.13-fu1-harness-surgery` · Story: `v0.13-fu1` · Status: implemented

## Problem

Two coupled failures blocked v0.13 story execution (PRD `prd-imoveis-2026-08-05` §6.2 gate). **Pain:** `validate.sh`/`finish-feature.sh` targeted the primary compose project — every validation could recreate the primary Postgres container and migrated the live `realestate` DB, repeatedly resetting the only copy of the scraped data (isolation existed at the DB level, not the container level). **Mandate:** CLAUDE.md still enforced the retired feature-pipeline/PR/CI regime and forbade the BMad dev skills that the ADR 0005 BMad-SoR + bmad-loop pivot requires.

## Approach

- **Ephemeral validation stack (CAP-1):** new `docker-compose.test.yml` (postgres with the primary's own `Dockerfile.postgres` for image parity, plus redis; docker-assigned ports; no named volumes) owned by `scripts/agent/test-stack.sh` under project `${COMPOSE_PROJECT_NAME:-imoveis}-test`. `validate.sh` derives `DATABASE_URL`/`REDIS_URL` from it and runs alembic host-side — the primary project is never touched by any validation path.
- **Fail-closed destruction (CAP-2):** `teardown.sh` reads the compose project from `.env.local` only (inherited env never trusted), refuses ambiguous or primary identities; `--primary` is an explicit operator override that can never wipe volumes.
- **Explicit primary migration (ex-OQ-1):** new `scripts/agent/migrate-primary.sh`, guarded by the backfill runner's existing TTL'd heartbeat (`backfill:gemma:active`, `src/core/backfill_runner.py` `Heartbeat`, TTL 300s). Live key ⇒ refuse; absent ⇒ pass in milliseconds; unreachable Redis ⇒ fail closed. Stale pacer keys never block.
- **Local, PR-less finish (CAP-8):** `finish-feature.sh` = feature-doc gate → `validate.sh all` (red blocks the merge) → local squash-merge into `main` → mandatory `git push origin main` → cleanup. GitHub is backup, not gate.
- **CI absorption (CAP-9):** `ci.yml` + `sonar-project.properties` deleted; `nightly.yml` trimmed to the live scraper drift canary; `validate.sh` now runs `pre-commit run --all-files` (closes the CI-only lint-scope gap, e.g. F401 outside `src/`); `no-commit-to-branch main` hook removed (main now advances via local squash commits by design); `docs.yml` + advisory dependabot kept.
- **BMad-only skill surface (CAP-3/6):** the 7 non-BMad skills deleted from `.claude/skills/` and `.cursor/skills/`; their load-bearing discipline moved inline into CLAUDE.md; `_bmad/custom/{bmad-dev-story,bmad-quick-dev,bmad-dev-auto}.toml` bind every dev loop to the gates (no raw pytest, no primary compose actions).
- **Doc surfaces rewritten (CAP-4/5/7):** project CLAUDE.md, global `~/.claude/CLAUDE.md`, `.cursor/rules/imoveis-core.mdc`, `~/.cursor/rules/agent-hygiene.mdc`, `docs/{harness-troubleshooting,development-guide,deployment-guide,source-tree-analysis}.md`, ADR 0001–0004 amendment notes, `_bmad-output/project-context.md` — zero feature-pipeline/PR/CI/Linear instructions remain; legacy `BIN-*` docs and `chats_history/` untouched.

## How to Test

1. Primary-safety (CAP-1): start `docker events --filter label=com.docker.compose.project=imoveis` in one shell, run `bash scripts/agent/validate.sh all` in another — zero events; `pg_dump --schema-only` + rowcounts of `realestate` identical before/after.
2. Drift guard (CAP-2): identity comes from the **file**, so probe the file, not the environment — (a) from the primary checkout (`.env.local` names `imoveis`): `bash scripts/agent/teardown.sh` refuses (primary, no `--primary`), regardless of any `COMPOSE_PROJECT_NAME` env value; (b) temporarily comment the `COMPOSE_PROJECT_NAME` line out of a scratch worktree's `.env.local`: teardown refuses (ambiguous identity); (c) `.env.local` absent: refuses. All nonzero exit.
3. Heartbeat guard: set `backfill:gemma:active` in primary Redis → `bash scripts/agent/migrate-primary.sh` refuses; delete the key → passes.
4. Lint parity (CAP-9): plant an unused import in a scratch `.py` outside `src/` → `bash scripts/agent/validate.sh fast` fails; remove it.
5. Regime sweep (CAP-4/5): `grep -rniE 'feature-pipeline|babysit|linear|pull request|gh pr|sonar' CLAUDE.md .cursor/rules docs/*.md` — no instruction-bearing hits.
6. Full gate:
   ```bash
   bash scripts/agent/validate.sh all
   ```

## Notes / Follow-ups

- **Adversarial review hardening (applied in this story):** `--skip-validate` restricted to docs-only branches (mkdocs gate still runs — no zero-gate path to `main`); worktree finish refuses to commandeer a primary checkout that isn't idle on `main`; main-moved-since-validation guard (exit 2) before squash-merge; merge-commit failure restores the workspace branch; empty squash handled; conflict-class failures really exit 2; feature-doc gate accepts bare-key branches (`feat/v0.13-fu1`) and is dry-run-safe; `--keep-branch` still prunes docker temps; test-stack env exports are `%q`-quoted (metacharacter passwords survive `eval`); test-stack/teardown/migrate-primary parse identity from `.env.local` (tolerating `export`/quotes) and require compose v2; teardown drops the ephemeral stack even when refusing the primary; pre-commit vendored-dir exclusion is per-style-hook only (`detect-private-key`/`check-added-large-files` stay global; `_bmad/custom/` stays linted).
- **No vulnerability scanning remains post-surgery** (ci.yml Trivy + nightly pip-audit/npm-audit deleted per OQ-4; dependabot advisory-only). Logged in the deferred-work ledger — decide whether a local advisory step or a non-gating scheduled audit is wanted.
- **Backfill-heartbeat TOCTOU:** migrate-primary's guard is check-then-act; a backfill starting mid-migration isn't excluded (would need a runner-honored mutual-exclusion key — product code, out of scope). Ledgered.
- **Global `~/.claude/skills/` legacy copies** of babysit-pr / code-review / epic-completion / harness-retrospect / security-scan / bmad-linear-bridge were unshadowed by the project-skill deletion — deleted too (user-approved during this story); no PR/Linear-era skill surface remains anywhere.

- **Worktree named volumes:** non-primary `teardown.sh` still removes the worktree project's own named volumes (`down -v --rmi local`) — pre-existing, documented isolation behavior; the SPEC's "no named-volume deletion" constraint is enforced where it matters (primary + all new script paths). The primary path can no longer reach `-v` at all.
- **Linear MCP connector:** still configured in the local harness config; with all Linear instructions gone, consider removing the connector so no agent rediscovers it (config-level change, outside repo scope).
- `imoveis-test-postgres`/`imoveis-test-redis` images match the `imoveis-*` keep-glob in `docker-cleanup-lib.sh`, so the test stack's built image survives cleanup (cheap re-up); worktree variants (`imoveis-wt-*-test-*`) are pruned as temporaries.
- The old "rebuild API image before `validate.sh backend`" rule is obsolete — validation no longer runs anything from the API image (host-side alembic + host pytest against the ephemeral stack).
