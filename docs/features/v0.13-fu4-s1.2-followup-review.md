# s1.2 follow-up review — RoutingAIClient lifecycle hardening + dispatch coverage

> Feature branch: `feat/v0-13-fu4-s1-2-followup-review` · Story: `v0.13-fu4` · Status: implemented

## Problem

Story v0.13-s1.2 shipped with `followup_review_recommended: true`: its review pass had itself introduced changes (the query-side embedding routing in `src/api/properties.py` and the `RoutingAIClient` lifecycle overrides) that no adversarial review layer ever saw. This follow-up ran the full three-layer review (Blind Hunter, Edge Case Hunter, Acceptance Auditor) on that merged review delta and fixed what survived triage.

## Approach

- Three independent cold-context review layers on the merged `11ceaf5` diff, triaged per the code-review workflow: 0 decision-needed, 3 patch, 1 defer, 10 dismissed (full log in the s1.2 spec's Review Findings section).
- `RoutingAIClient.__aenter__` now unwinds already-opened sessions when a later enter fails (the exact leak its pass-1 docstring claimed to prevent), rejects re-entrant use instead of silently clobbering `self._stack`, and `__aexit__` delegates the in-flight exception to the underlying session contexts via `stack.__aexit__(...)` instead of `aclose()`.
- Dispatch coverage extended to all four routed methods (`summarize_deal`→DEAL_VERDICT, `embed`→EMBEDDING were unasserted — a transposition bug would have passed the suite).
- The s1.2 spec's frozen intent contract was amended to match shipped, test-locked behavior (live cloud-degrade logs DEBUG, not WARNING — pass-1 applied the demotion without updating the contract).
- The one deferred finding (backfill-mode cloud EMBEDDING would break read/write vector-space symmetry) went to the deferred-work ledger for story 1.3, which owns the backfill runner seam.
