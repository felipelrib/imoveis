# Dependency audit gate — advisory `pip-audit` + `npm audit` stage in `validate.sh all`

> Feature branch: `bmad-loop/20260810-193244-9de6/dw-decision-dw-2` · Story: `v0.13-fu9-dependency-audit-gate` · Status: implemented

## Problem

CI retirement (v0.13-fu1 / OQ-4) deleted the Trivy filesystem scan and the nightly `pip-audit` / `npm audit` jobs on the premise that the local gates covered them. They did not: no local gate audited dependencies for known vulnerabilities, and Dependabot is advisory-only with no checks running on bot PRs. Between v0.13-fu1 and this change, nothing in the repository scanned `requirements.txt` or `frontend/package-lock.json` for CVEs at any point in the ticket-to-ship cycle.

## Approach

- **New self-contained script** `scripts/agent/audit-deps.sh`: runs `pip-audit` over `requirements.txt` and `npm audit` over `frontend/`, prints per-source findings plus a summary count.
- **Advisory by construction.** The stage is wired into `validate.sh all` only, through a `run_audit()` that follows the existing informational-only precedent (the `alembic check` block in `run_contract`): `&& ok … || warn …`, never `rc=1`. A run full of advisories still prints `VALIDATION PASSED`. Alternative considered and rejected: making it merge-blocking, which would let an upstream advisory published overnight block an unrelated merge and push agents toward suppression files.
- **JSON, never human output.** Both tools exit non-zero for "vulnerabilities found" as often as for "tool/network failure", so the script decides purely on whether the JSON payload parses (`pip-audit --format json`, `npm audit --json`). Unparseable ⇒ degraded ⇒ visible skip.
- **Visible degradation, never silence.** Missing `pip-audit`, missing `frontend/package-lock.json`, missing python, or an unreachable network each print a `[WARN] … — skipping` line and still exit 0, so offline merges keep working (same graceful-degrade shape as `validate-ai.sh`'s unreachable-Ollama path). "Nothing was audited" counts as degradation too: an empty pip-audit resolution, or `skip_reason` on every package, yields a legitimate advisory count of `0` that must never be reported as a clean tree.
- **npm findings are named, not just counted.** Each is printed as `pkg (severity, DIRECT dependency|transitive) — fix: …`. A severity histogram alone is untriageable — it is exactly what hid a high-severity *direct runtime* dependency behind "5 high, transitive toolchain noise" during review.
- **Skipped once the gate is red.** `run_audit` reads (never assigns) `rc` and short-circuits when validation has already failed, so a doomed run does not spend minutes of network on output nobody can act on.
- **`--strict` for operators only.** Identical output, exit 1 when findings exist **or when either audit degraded** — an operator security check must not report green having audited nothing. Only the default mode is unconditionally exit 0 (that is what keeps the gate advisory). `validate.sh` never passes `--strict`; a unit test locks that.
- **Bounded network calls.** Each tool invocation runs under `timeout $AUDIT_TIMEOUT` (default 180s), so a stalled registry degrades to a skip instead of hanging `validate.sh all` — and therefore `finish-feature.sh` — indefinitely.
- **`PIP_AUDIT_BIN` / `NPM_BIN`** override the resolved binaries so tests exercise the real script's degradation path without a network.

## New Dependencies

No runtime dependencies. `requirements.in` / `requirements.txt` and `package-lock.json` are untouched — no bumps, no regeneration.

`pip-audit` is a **gate-only dev tool**, declared in `scripts/agent/setup-tools.sh`'s `PYTHON_TOOLS` array (alongside `pre-commit`, `flake8`, `isort`, `autoflake`, `pytest-timeout` — none of which are in `requirements.in` either). `validate.sh` sources `setup-tools.sh`, so it installs on first use.

## How to Test

1. Full advisory run (exits 0 whether or not advisories exist):
   ```bash
   bash scripts/agent/audit-deps.sh; echo "EXIT=$?"
   ```
2. Degraded path — stubbed tools stand in for "not installed / offline"; expect two `[WARN] … skipping` lines and `EXIT=0`:
   ```bash
   PIP_AUDIT_BIN=/bin/false NPM_BIN=/bin/false bash scripts/agent/audit-deps.sh; echo "EXIT=$?"
   ```
3. Operator strict mode — exit 1 when findings exist **or** when either audit degraded (a skip is not a clean bill of health):
   ```bash
   bash scripts/agent/audit-deps.sh --strict; echo "EXIT=$?"
   ```
4. Invariants + no audit output in the fast scope:
   ```bash
   bash scripts/agent/validate.sh fast
   ```
5. Full gate — the audit stage appears and the verdict is unchanged by it:
   ```bash
   bash scripts/agent/validate.sh all
   ```

## Notes / Follow-ups

- **Deviation from "declare it in `requirements.in`":** `pip-audit` was added to `scripts/agent/setup-tools.sh`'s `PYTHON_TOOLS` rather than `requirements.in`, because `requirements.txt` is the `pip-compile --strip-extras` **runtime** lockfile that builds the API image. Adding an audit tool there would ship it (and its transitive deps) to production and would require a network `pip-compile` regeneration inside an unattended run. `PYTHON_TOOLS` is this repo's de-facto dev-tool declaration and is auto-invoked by `validate.sh`.
- **Escalation rule (do not regress):** a real finding is resolved by a deliberate dependency bump, revalidated through the normal gate. Never mute the tool, never add `.trivyignore`-style suppressions, never soften with `--audit-level`, and never make the stage merge-blocking.
- A skipped audit is not a clean audit: `skipped python + skipped npm` in the summary means the stage degraded, not that dependencies are vulnerability-free.
- **BUG (Medium)**: the first-run baseline below is real, fixable, and currently tracked nowhere but this bullet — the detector shipped while the vulnerabilities it found did not get a story. Fix hint: mint a `v0.13-fu10` bump story (or a deferred-work entry) covering at minimum `react-router-dom` and `cryptography`, both of which have fixes published.
- **First run's baseline (2026-08-11, informational — deliberately not bumped here, per the "no dependency bumps in this change" boundary):**
  - python 2: `cryptography 49.0.0` / PYSEC-2026-3552 (**fix 50.0.0 published**); `ecdsa 0.19.2` / PYSEC-2026-1325 (no fix published — the same advisory already justified in `.trivyignore`).

Verified via `npm audit --json`: it is a direct entry in `frontend/package.json` `dependencies`, so it ships in the browser bundle.
- **Do not dismiss npm findings as toolchain noise without checking `isDirect`.** The summary counts cover dev *and* runtime dependencies undifferentiated (`npm audit` is run without `--omit=dev`, so the count is not a prod/dev split). The stage now prints `isDirect` and fix availability per package, so this is readable straight from the gate log; `cd frontend && npm audit --json` remains the deeper view (dependency paths, advisory URLs).
- **`--strict` and the standing baseline.** Because suppressions are forbidden by design, the known-unfixable `ecdsa` advisory (accepted risk, documented in `.trivyignore` as CVE-2024-23342 — which no remaining scanner reads) keeps the summary permanently amber. There is no baseline file or ratchet, so a *new* critical does not stand out from the standing set; read the per-finding lines, not the colour. That is inherent to the chosen advisory-log-only option — see the deferred-work ledger for the follow-ups.
