# Operações backfill card + coverage visibility — the multi-day cloud backfill becomes an operator surface

> Feature branch: `bmad-loop/20260806-010958-6ecb/1-6-operacoes-backfill-card-coverage-visibility` · Story: `v0.13-s1.6` (absorbs `v0.13-s1.4`) · Status: implemented

## Problem

Story 1.5 shipped the `/admin/backfill/*` control plane with no consumer: the operator still started, paused and watched a six-day cloud enrichment run from a terminal, and FR-28's "graduates from `scripts/dev` to an operator-facing operation" stopped one layer short of the operator. Worse, nothing anywhere answered "how much of the DB is actually enriched" — story 1.4, the DB-derived coverage endpoint this UI was specified to read, never landed: it escalated inside this same bmad-loop run on a branch-state blocker (an unmerged story-1.3 follow-up branch) that has since been resolved and merged, leaving `1-4-enrichment-coverage-telemetry` at `backlog`. Story 1.6's acceptance criteria consume that endpoint directly (`Cobertura de IA N%`, the per-signal breakout), so the UI was undeliverable without it.

## Approach

- **Absorb story 1.4 rather than block the epic again.** The coverage endpoint is built to 1.4's own acceptance criteria in `epics.md`, in this branch, and both story keys are reconciled in `sprint-status.yaml`. Blocking a second time would have stalled Epic 1 on an already-resolved problem.
- **Coverage is DB-derived, full stop (FR-29).** Fractions, `remaining`, and throughput come from SQL over `properties` / `metrics_scoring` / `pipeline_metric_snapshots`. Redis is consulted for exactly one bit — is a run holding the lease — because liveness is not a progress metric. The runner's checkpoints never become a second source of progress.
- **Layering follows AD-1:** pure fraction/ETA math in framework-free `src/core/enrichment_coverage.py` (TDD tier, injected `today` so tests are deterministic), all SQL in `src/adapters/db/enrichment_coverage_queries.py`, and a thin `GET /admin/enrichment/coverage` route that only wires the two together.
- **Honest absence over zero (UX-DR3).** `total == 0` yields `fraction: null`, not `0.0`; throughput/ETA/projected date are `null` whenever no run is active or fewer than two usable snapshots exist in the window. The UI omits the corresponding lines and chips entirely instead of rendering `0%` or a fabricated ETA.
- **A failed read is absence too.** The hook fetches status and coverage independently (`Promise.allSettled`) with a separate error per source, so a Redis-side status 500 no longer suppresses the entirely DB-derived coverage figures. Whichever read failed drops its data and says so in one line (`operations.statusUnavailable` / `operations.coverageFailed`); the matching Painel chip disappears rather than freezing on numbers nobody just measured. Overlapping loads carry a generation stamp, so a mutation's refresh can never be overwritten by an older interval tick still in flight.
- **`active` is liveness, `state` is only activity.** Every control keys off the lease: the state key expires under a slow row (DW-20) and decays to `idle` while a run is very much alive, and pausing off `state === 'running'` locked the operator out exactly then. Start is additionally refused up front when the plane is `blocked`, a primary migration holds the gate, or a start request is already pending; pending `pause`/`stop`/`start` levels the runner has not applied yet render as their own line, so a pause does not look like a lost click.
- **A start that nothing will honor says so.** `POST /admin/backfill/start` returns 202 with `runner_present: false` when no host-side `--serve` supervisor is waiting, and `already_requested: true` when the request was already queued. Each outcome gets its own toast; only a genuinely new request that a runner is listening for reports success.
- **Numbers are never rounded into a claim.** The quota percentage is clamped to `[0, 100]` (retries push `consumed` past the daily limit), singular/plural have their own keys instead of `~1 dias`, a rate below one row a day is stated as such rather than as `~0 imóveis/dia`, and `wholePercent` refuses to round `0.996` up to a finished `100%` or a small non-zero fraction down to `0%`.
- **ETA is reachable.** `remaining` mirrors the runner's own candidate predicate *including the photo gate*, so rows that can never clear do not inflate the projection — the v0.13-fu3 dead-completion-branch lesson applied to the dashboard. A drift-lock unit test pins that copied predicate (and the min-photos expression) against `scripts/dev/backfill_gemma.py`, because two hand-copied SQL fragments that silently disagree would make the dashboard lie with a green suite.
- **The throughput window follows the run, not the clock.** The rate is the `pipeline_metric_snapshots` delta over the trailing 24h, but the window start is clamped to the lease's `acquired_at` when that is more recent — otherwise a run 30 minutes old has its rate averaged across 23.5 idle hours and the operator reads an ETA overstated by more than an order of magnitude. Fewer than two usable points, or a non-positive delta, still yields `null` rather than a guess.
- **The ETA is an approximation, and says so.** `remaining` counts active, photo-gated, unscored rows while the rate comes from a corpus-wide `ai_score > 0` count that includes live-pipeline enrichment; and `remaining` does not subtract quarantined rows, because that count needs the O(rows-ever-attempted) Redis attempt-ledger scan story 1.5 deliberately kept off polled routes. Both approximations are documented on the query module and on `BackfillProgressModel` instead of being presented as exact.
- **All five signal types are surfaced**, not the four the UX mockup enumerates: story 1.4's AC says "per Story 1.1 signal type", and hiding a measured signal (`deal_verdict`) would be less honest than the extra row.
- **Meia-noite tokens are minted without a restyle.** Non-colliding roles (`--surface-card`, `--border-hairline`, `--health-warn`, …) land on `:root` under their DESIGN.md names; the four roles whose names collide with the legacy palette (`--text-primary/secondary/muted`, `--accent`) are redefined inside a `.meia` scope carried only by the new components, so no existing page changes appearance. The new cards deliberately do **not** carry the legacy `.card` class: `.card:hover` (0,2,0) outranks `.ops-card` (0,1,0), so a shared card kept the legacy accent glow DESIGN.md rules out and inherited `backdrop-filter: blur(20px)` untouched. `.ops-card` owns its own padding and DESIGN.md depth (one soft shadow + a 1px inset highlight, no glow), which is what makes "tokens without a restyle" true in both directions. Tokens and rules nothing consumes (`--health-ok`, `--surface-elevated`, `--radius-meia-sm`, `.health .dot*`) are not minted at all.
- **Default locale flips to pt-BR** on both sides (frontend `DEFAULT_LOCALE`, formatter fallback, `<html lang>`, `configs/app_config.yaml`, the pydantic default), with the `ui.locale` preference still switching. Every new string exists in both catalogs.

## How to Test

1. Full gate (what the merge runs):
   ```bash
   bash scripts/agent/validate.sh all
   ```
2. Backend only (coverage SQL against the ephemeral test DB + contract suite):
   ```bash
   bash scripts/agent/validate.sh backend
   ```
3. Manually, with the primary stack up and an API credential pasted into the UI:
   - open **Operações** — with no run, the card shows `inativo` and **no** budget/ritmo/ETA lines; the coverage card lists all five signals as text percentages.
   - start a run (a host-side `python scripts/dev/backfill_gemma.py --serve` supervisor must be waiting, per story 1.5) — the state flips to `em execução`, the three lines appear, and the warning line about `migrate-primary.sh` shows up.
   - press start again while the lease is held — a toast names the active run; no second runner is requested.
   - press start with **no** `--serve` supervisor running — the toast says the request was recorded but nothing is listening, instead of reporting success.
   - press pause — the pending line appears (`pausa solicitada — aguardando o runner aplicar`) and the pause control stops accepting repeats until the runner applies it.
   - stop Redis (or revoke the credential) with the primary DB up — the card states that the control state is unavailable and drops its figures, while the coverage card keeps showing DB-derived percentages.
   - open **Painel** — the health strip carries `⚠ Backfill` with the run's own state word (`em execução`, `pausado`, …) and `Cobertura de IA N%`, where N is the minimum across signal types and the hover names which signal it came from.

## Notes / Follow-ups

- **Story 1.4 landed here.** `1-4-enrichment-coverage-telemetry` is annotated in `sprint-status.yaml` as implemented inside this branch and recorded `done` alongside `1-6` as this branch merges. The bmad-loop run state still carries 1.4's old `escalated` phase from the stale blocker, so a re-drive of that key would find the work already done. Its own feature doc — required per story key — is [`v0.13-s1.4-enrichment-coverage-telemetry.md`](v0.13-s1.4-enrichment-coverage-telemetry.md), which documents the endpoint against 1.4's acceptance criteria; this doc covers the consumer surfaces built on it.
- The toast provider is anchored top-right; DESIGN.md specifies bottom-anchored toasts. Re-anchoring is a shared-surface change every page inherits, so it was left alone — **BUG (Low)**: toast anchoring does not match the DESIGN.md toast spec — fix hint: re-anchor `ToastProvider` in its own change and re-run the full e2e suite.
- The page heading on Operações still reads `scraper.title` ("Controle de Scrapers") while the nav label is now **Operações** — **BUG (Low)**: nav label and page heading disagree — fix hint: align the `<h1>` copy with the nav key.
- The mockup's `dia N de ~M` counter is deliberately not implemented: neither the DB nor the control plane can honestly produce a run's start day.
- **The locale flip also changes the language new AI free text is written in.** `ui.locale` is not a chrome-only setting: BIN-101 made `infra.ui_locale.resolve_ai_output_language()` prefer the active UI locale (Redis `ui:locale` → `ui.locale`), and that value is what `adapters/ai/client.py` and the enrichment tasks pass as `output_language` for verdicts, visual and sentiment text. So on any deployment with no `ui:locale` override in Redis, newly enriched rows now get Portuguese free text while already-enriched rows keep the English they were written in — including, notably, mid-way through the very Gemma pass this card supervises. That alignment is BIN-101 working as designed for a pt-BR product (and the backfill re-enriches the corpus, so it converges), but it is a behaviour change this story's Code Map presented as chrome-only. No prompt or client code changed, so the `validate-ai.sh` hook was not triggered. To keep English enrichments, set the Redis `ui:locale` override to `en` via `POST /admin/locale`.
- The running warning line is driven by the wire's own `heartbeat_active` ("rows are being enriched right now"), which is exactly the `backfill:gemma:active` key `migrate-primary.sh` refuses on — not by re-deriving it from `active`/`state`, which disagree with it whenever the state key decays (DW-20). Its copy names `migrate-primary.sh`: `validate.sh` runs only against the ephemeral test stack and is safe during a live backfill (v0.13-fu1), and the first version of this line told the operator the opposite.
- Resume is offered only when a pause **level** is set and the lease is still held. `pending_requests` reports levels, not transient requests (`pending_control_requests` derives `pause` from `control.is_paused()`), so it stays set for the whole pause — the "waiting for the runner to apply it" line is the level minus the applied state, and `backing-off` is not resumable at all.
- `backfill.remaining` intentionally does not equal `total − enriched` for any single signal — it is the `ai_score`-based queue count with the photo gate applied, not a per-signal residual.
- A Redis outage 500s the coverage endpoint (consistent with `/admin/backfill/status`) even though the coverage figures themselves are DB-only — **BUG (Low)**: coverage could degrade to `active: null` instead of failing — fix hint: guard only the liveness read in the route and mark liveness unknown.
- `remaining` double-counts a property carrying several unscored `metrics_scoring` rows — **BUG (Low)**: the LEFT JOIN has no DISTINCT — fix hint: the identical expression lives in `scripts/dev/backfill_gemma.py::_census` and is now drift-locked to this one, so fix both together (deferred to the ledger).
- Review pass 1 (2026-08-11) applied 24 patches on top of the first implementation, including three with operator-visible consequences: the throughput window clamp above, pause keyed off the lease instead of the decaying state key (a live run whose state decayed to `idle` could not be paused), and the first real SQL correctness tests (previously every query only ever ran against an empty DB).
- Review pass 3 (2026-08-11) closed the last member of the family the two earlier passes had been working through — a figure gated on *liveness* where it should have been gated on *work*. The rate and the ETA were shown for any lease holder, so pausing a run left its pre-pause pace and a completion date on screen; both now additionally require the run not to be `paused`, `backing-off` or `blocked` (see the Design Notes in the spec for the settled division between `active`, `heartbeat_active` and the stall states). The same pass gave the Painel chip the run's real state word instead of a fixed "em execução", stopped an orphaned pause level from claiming for a week that a runner was about to apply it, and made a rejected credential say so instead of blaming the control plane.
