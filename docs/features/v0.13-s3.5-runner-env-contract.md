# Runner env contract — the enablement surface that works, a preflight that reads both inputs, and a gate that stops inheriting operator env

> Feature branch: `feat/v0.13-s3.5-runner-env-contract` · Story: `v0.13-s3.5` · Status: implemented

## Problem

Story [`v0.13-s3.1`](v0.13-s3.1-backfill-runner-hosting.md) gave the cloud
backfill supervisor a committed home (ADR 0006). Its operator handoff then
surfaced two defects in that same delivery.

**DW-31 — the documented way to enable it is the way that breaks the gate.** The
runbook told the operator to set `ai.enrichment_routing.{visual,sentiment,deal_verdict}`
to `gemma` in the **committed** `configs/app_config.yaml`. That file must route
every task class to a local backend (NFR-1) and
`src/tests/unit/test_config.py::test_enrichment_routing_default_all_local` pins
it, so the operator had two bad outcomes only: commit the edit and redden
`validate.sh fast` for every later story, or leave it uncommitted and break
`bmad-loop validate`'s clean-worktree precondition. The installer compounded it:
`routing_has_cloud_backend()` awk-grepped the YAML alone, so a host correctly
enabled through the env override the unit *already* reads was told on every
`--check` that the unit "would exit at startup and restart forever".

**DW-33 — `.env.local` is the runner's `EnvironmentFile` *and* the file the gate
sources.** `validate.sh:60` and `finish-feature.sh:46` did `set -a; source
.env.local`, so anything an operator put there for the runner became ambient
pytest env: the cloud key, the **primary** `DATABASE_URL` (seen by unit tests,
which run before the ephemeral stack exports its own), and the generic
`IMOVEIS_<SECTION>__<KEY>` channel that rewrites config under any `load_config()`
call. Observed 2026-08-12: the three routing overrides injected a *partial*
routing map into an unrelated Redis test's minimal fixture YAML, failing
`AIConfig`'s totality validator — a Redis test failing with a routing error.

## Approach

- **The per-host env override is the sanctioned enablement surface**, named
  identically on every operator-facing surface (env template, `docs/setup.md`,
  `docs/deployment-guide.md`, installer warning, ADR 0006 amendment, story 3.1's
  follow-up): `IMOVEIS_AI__ENRICHMENT_ROUTING__{VISUAL,SENTIMENT,DEAL_VERDICT}=gemma`
  in the git-ignored `.env.local`. `_apply_env_overrides` sets those leaves over
  the YAML-loaded map, so the map stays **total** for story 1.1's startup
  validator, the scalar `ai.backend` stays local (the live Celery path is
  untouched, AD-13), `embedding` still degrades local even for backfill (DW-5),
  and nothing enters git. The unit needs no change — it already reads the file.
- **Preflight resolves the effective map, not one of its inputs.**
  `routing_effective_value()` lays the env file's override over the YAML block
  exactly as the loader does — the override wins for that class, whichever way it
  points — and `routing_scope_verdict()` then judges the resulting map the way
  `--serve` judges it: **every** class in the backfill scope (`visual`,
  `sentiment`, `deal_verdict`) cloud-routed, and all on the **same** backend
  (`ok` / `local <classes>` / `mixed <class>=<backend>,…`). The `export`-prefix
  failure now covers routing overrides too — `EnvironmentFile=` is not a shell,
  so `export IMOVEIS_…=gemma` would never reach the unit and the host would
  crash-loop with a certified-OK install — and so do the two overrides that are
  fine for systemd and fatal for `AppConfig`: a backend name in the wrong case or
  an unknown task class (both case-sensitive `ConfigError`s at startup), and an
  empty value, which still replaces the YAML entry with `''`.
- **The precedence rule stays in bash, deliberately.** Preflight is a
  dependency-free, pre-install check that must still work on a host whose venv
  cannot import the app — that is one of the failures it exists to catch — so
  calling `load_config()` from a root-privileged installer was rejected. The cost
  is a second expression of "env wins over YAML"; both directions are unit-tested
  by invoking the real script, so the mirror cannot drift silently.
- **The env collision is closed at the boundary that creates it.**
  `scripts/agent/lib.sh::load_workspace_env` is a **default-deny** allowlist
  reader (last assignment wins; quotes, inline comments and CR stripped; values
  literal — nothing in the file is executed). Both gate scripts use it; narrowing
  only one would leave the bleed, since `finish-feature.sh` spawns `validate.sh`.
  `test-stack.sh`, `ensure-test-db.sh`, `run-services.sh` and
  `migrate-primary.sh` are separate processes that re-source the file themselves
  and keep full access.
- **A suite-wide guard is the second layer, not a duplicate.**
  `src/tests/conftest.py` strips the `IMOVEIS_*` channel for every test, making
  the suite deterministic however it was invoked (a bare `pytest` in a shell that
  sourced `.env.local`, an IDE runner, an exported variable — the case no
  file-reading loader can reach). The rule is **default-deny over the whole
  prefix**, not "names containing `__`": `_apply_env_overrides` applies every
  prefixed variable, and `IMOVEIS_AI=x` — no `__` at all — replaces the entire
  `ai` section with a string. The only survivors are the two named escape hatches
  `IMOVEIS_ALLOW_PRIMARY_DB_WIPE` / `IMOVEIS_ALLOW_PRIMARY_REDIS_WIPE` (BIN-71 /
  BIN-117), which fixtures read and `infra.config` does not. The per-module
  `IMOVEIS_*` loop added to `test_celery_app.py` on 2026-08-12 folds into it
  rather than living on as a divergent copy.
- **Rejected (DW-33 alternative a): a second `EnvironmentFile` for the unit.** It
  doubles the operator's env contract (`GEMINI_API_KEY`/`DATABASE_URL` in two
  places), rewrites the installer and doc contract story 3.1 had just shipped,
  and still does not stop an operator putting `IMOVEIS_*` in `.env.local` — it
  narrows one symptom instead of the class.
- **Rejected (DW-33 alternative c *alone*): suite-wide stripping only.** A root
  conftest fixes the config channel but leaves the operator's primary
  `DATABASE_URL` and cloud key in the gate process, and it is invisible to
  anything that is not a pytest fixture. It is kept as the second layer.

## How to Test

```bash
bash scripts/agent/validate.sh backend
```

`backend` (not just `fast`) is the meaningful scope here: it proves the narrowed
`.env.local` load did not starve integration/contract of `DATABASE_URL` /
`REDIS_URL`, which now come only from the ephemeral test stack.

Installer preflight, unprivileged and hermetic (no sudo, no containers):

```bash
BASE='GEMINI_API_KEY=x\nDATABASE_URL=postgresql://u:p@localhost:5432/realestate\n'
R=IMOVEIS_AI__ENRICHMENT_ROUTING__

# 1. cloud via the per-host override → ready, NO routing warning.
#    ALL THREE scoped classes: --serve drives one client and refuses anything less.
printf "$BASE${R}VISUAL=gemma\n${R}SENTIMENT=gemma\n${R}DEAL_VERDICT=gemma\n" > /tmp/env.cloud
bash scripts/install-backfill-runner.sh --check --force --env-file /tmp/env.cloud
#    → "> Effective backfill routing: gemma for visual sentiment deal_verdict"

# 2. genuinely all-local → warning naming the env override (never a YAML edit)
printf "$BASE" > /tmp/env.local
bash scripts/install-backfill-runner.sh --check --force --env-file /tmp/env.local

# 3. PARTIAL scope (one class only) → warning naming the classes still local.
#    This is the shape the old preflight certified as ready; the unit crash-looped.
printf "$BASE${R}VISUAL=gemma\n" > /tmp/env.partial
bash scripts/install-backfill-runner.sh --check --force --env-file /tmp/env.partial
#    → "These scoped task classes do not resolve to a cloud backend on this host:"
#      "  sentiment deal_verdict"

# 4. two cloud backends across the scope → mixed-backend warning
printf "$BASE${R}VISUAL=gemma\n${R}SENTIMENT=gemini\n${R}DEAL_VERDICT=gemma\n" > /tmp/env.mixed
bash scripts/install-backfill-runner.sh --check --force --env-file /tmp/env.mixed

# 5. override hidden behind `export` → preflight failure (exit ≠ 0)
printf "$BASE" > /tmp/env.export
printf "export ${R}VISUAL=gemma\n" >> /tmp/env.export
bash scripts/install-backfill-runner.sh --check --env-file /tmp/env.export

# 6. an override AppConfig would reject at startup → preflight failure (exit ≠ 0):
#    a wrong-case backend (`GEMMA`), an unknown class (`VISUALS`), an empty value.
printf "$BASE${R}VISUAL=GEMMA\n" > /tmp/env.badcase
bash scripts/install-backfill-runner.sh --check --env-file /tmp/env.badcase
```

Operator (privileged, **not** performed by an agent): add the three overrides to
the real `.env.local`, re-run `bash scripts/install-backfill-runner.sh`, then
press Start in Operações and confirm the run begins with no crash-loop.

## Notes / Follow-ups

- **Adding a key to the allowlist is a deliberate act.** `WORKSPACE_ENV_ALLOWLIST`
  in `scripts/agent/lib.sh` is default-deny: a variable a future `.env.local`
  gains does not reach the gate until it is listed. It must never gain
  `DATABASE_URL`, `REDIS_URL`, `GEMINI_API_KEY` or anything `IMOVEIS_*` — the
  test DB/Redis URLs come from the ephemeral test stack, and the config-override
  channel must stay out of pytest.
- **ANY → ALL: the verdict was corrected mid-story.** The first cut of the
  preflight (and the I/O matrix row it came from) asked "does *at least one* task
  class resolve to a cloud backend?". `--serve` asks something stricter:
  `scripts/dev/backfill_gemma.py::_resolve_backfill_backend` refuses unless
  **every** class in `DEFAULT_BACKFILL_SCOPE` (`visual`, `sentiment`,
  `deal_verdict`) is cloud-routed **and they all name the same backend** — it
  drives one client and has no local execution mode. Under the ANY reading a host
  with only `…__VISUAL=gemma` was certified ready and then crash-looped every
  10 s — the *same* false OK DW-31 was filed for, pointing the other way. The
  preflight now mirrors `_resolve_backfill_backend` exactly, and
  `TestEffectiveRoutingPreflight` pins each branch (whole scope → ready, partial
  scope → warning naming the classes still local, split backends → mixed
  warning).
- **The precedence rule now lives in two places** (`_apply_env_overrides` in
  Python, `routing_effective_value` + `routing_scope_verdict` in bash). That is
  the accepted cost of a preflight that works without importing the app; the
  paired tests fail if either side drifts.
- **`configs/app_config.yaml` is an operator-facing surface too.** Two prose
  comments in it still told the reader to set
  `ai.enrichment_routing.{visual,sentiment,deal_verdict}: gemma` — the very
  instruction DW-31 closed everywhere else, and the first thing an operator
  reads when they open the config. Both were reworded to point at
  `IMOVEIS_AI__ENRICHMENT_ROUTING__*` in `.env.local`. **Comments only:** every
  routing value stays `ollama`, so `test_enrichment_routing_default_all_local`
  is untouched and still pins the all-local invariant.
- **The privileged path is still unverified by the agent.** Installing the unit,
  restarting it and observing a real Start press are operator actions; only
  rendering and the preflight branches are covered by tests.
- Related: `DW-31` and `DW-33` (both closed by this story), story
  [`v0.13-s3.1`](v0.13-s3.1-backfill-runner-hosting.md) (the delivery this
  corrects), [ADR 0006](../adr/0006-backfill-runner-hosting.md) (amended), and
  stories 3.2–3.4 (runner internals — no files shared with this story).
