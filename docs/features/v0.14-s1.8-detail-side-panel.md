# Detail side panel — a property opens on the right, with the percentile sentence and the stored cost breakdown

> Feature branch: `feat/v0.14-s1.8-detail-side-panel` · Story: `v0.14-s1.8` · Status: implemented (frontend only; no operator step)

## Problem

A property opened in a centered modal:

- it hid the grid and the map;
- it used the legacy glass palette, not the Meia-noite tokens;
- it labelled the legacy `percentile_rank*` as `Percentil`, which UX-DR8 forbids;
- it showed cost from the legacy `base_price` / `condo_fee` / `iptu` fields, not from the stored Total Monthly Cost of Story 1.2;
- opening a favourite reloaded the list and flipped the view from Favoritos to Imóveis.

## Approach

- **Right-side panel, not a dialog (UX-DR4).** `aside` fixed to the right edge, one level deep, `Esc` closes, URL stays `/properties/:id`. Nothing behind it is made inert.
- **Partial scrim.** In the grid view the scrim runs from the nav sidebar's right edge to the panel's left edge; a click on it closes the panel. In the map view there is no scrim: the panel covers the right part of the map and the rest stays usable.
- **The page behind does not move.** Opening and closing do not refetch the list, do not move the window scroll (focus is moved with `preventScroll`), do not remount the map and do not touch filter state. Focus goes into the panel on open; on close it goes back to the element that had it, unless the user has meanwhile focused a control of the page.
- **`Esc` closes only when nothing else used it.** An `Esc` a dropdown already handled (`defaultPrevented`) or pressed while the save-search dialog is open does not close the panel. The city and neighbourhood multiselects consume `Esc` only while their dropdown is open, so with focus on a closed trigger the key closes the panel.
- **Favourite and watch changes reach the page.** Toggling the star or the bell in the panel updates the page's favourite set or watch set at once (`onFavouriteChange`, `onWatchChange`), so the card behind shows the same state. In Favoritos the list behind the panel is reloaded when the panel closes, not while it is open; outside Favoritos closing reloads nothing.
- **Favoritos stays Favoritos.** A panel opened from Favoritos lives at `/properties/:id` with `state.returnTo = /favourites`; while it shows, the view behind it is still Favoritos.
- **Independent sections.** The shell renders one ordered list of section components. Each takes `{ property, priceHistory, t, locale }` and returns `null` when it has nothing to say. A later story (3.9, 5.9, 5.8) adds one file and one line.
- **One percentile rule for card and panel.** `percentileSentences` in `utils/percentile.ts` is built on `badgePercent`: the panel has a sentence exactly when the card has a badge, with the same N.
- **Cost is read, never computed.** `utils/listingCost.ts` turns the stored `listings[].cost` object into ordered rows. No arithmetic, no default, no fallback to the legacy fee fields.
- **The modal is gone, not hidden.** Component, styles, catalog keys and test selectors named after it are removed. The save-search dialog, which borrowed the modal classes, now has its own `.dialog*` rules.

### What the panel shows

| Part | Content |
|---|---|
| Actions | Watch control (`Alertar em N % de queda` + bell), favourite star, close |
| Header | Price (serif), percentile badge, neighbourhood name (serif), title, `quartos · m² · plataformas` |
| Gallery | Main photo and thumbnails |
| Por que este veredito | Percentile sentence(s), deal summary, statistical / visual / ad-claims analyses, feature and claim tags, the three scores as plain numbers |
| Custo mensal | One block per Listing that has a `cost` object |
| Histórico de preço | Line chart per listing type and platform; neutral ink, series told apart by stroke pattern (six patterns), which the legend swatches repeat. One point only: a note that two are needed |
| Preço por plataforma | One row per Listing: platform, type, published price, link to the ad, furnished / pets tags. With no Listing rows: the id-based `Ver original` link when the platform has one (BIN-158) |
| Características | Address, size, price per m², per-type scores |
| Qualidade do bairro | Score, four sub-scores, risk flags, notes |
| Descrição | The ad text |

The verdict and facts sections always render (the scores and the platform row are always there; a missing value reads as a dash). Every other section is absent when it has nothing to show.

### Percentile sentence

| Property | Sentence (pt-BR) |
|---|---|
| Listings of one type | `Está entre os N% mais baratos do bairro.` |
| Listings of both types, rent | `Está entre os N% mais baratos dos aluguéis do bairro.` |
| Listings of both types, sale | `Está entre os N% mais baratos das vendas do bairro.` |
| Stored value null, or above 0.5 | No sentence and no badge element |

N is the card's N (`0.2001` reads 21). The header badge reads `entre os N% mais baratos` for the listing type of the header price.

### Cost rows

| Stored state | Row |
|---|---|
| Component `known` | Label and the stored figure |
| Component `unknown` | Label and `não informado`; never 0, never a dash |
| `fees_bundled` | One row `Condomínio + IPTU` with the combined figure and the note `valor único publicado pela plataforma`; no separate condo or IPTU row |
| IPTU with `iptu_periodicity_source: annual` | The IPTU row carries `convertido do valor anual` |
| Total `complete` or `bundled` | `Total mensal` and the stored total |
| Total `incomplete` | `Total mensal`, `incompleto`, note `há valor não informado`; no number |
| Sale Listing (`not-applicable`) | Condo and IPTU rows only; no rent row, no total row |
| Listing without `cost` | No block for that Listing; no section when none has one |

### Product decisions taken in this story

| Decision | Chosen | Where |
|---|---|---|
| Scrim without a split layout | The app shows the grid or the map, never both, so the DESIGN.md state "grid dimmed with the map rail beside it" does not exist. Grid view: the scrim dims the grid. Map view: no scrim | `PropertyDetailPanel.tsx` (`viewType`) |
| URL | The open panel is in the URL, `/properties/:id`, as the modal was; closing returns to `/properties` or `/favourites` | `Properties.tsx` |
| When the sentence appears | Under the badge's cutoff: stored value at or below 0.5. Above it nothing is said, as on the card | `percentileSentences` |
| Wording of absence | Unknown component: `não informado`. Bundled: one row `Condomínio + IPTU`, note `valor único publicado pela plataforma`. Incomplete total: `incompleto`, note `há valor não informado` (en: `not published`, `incomplete`, `a value was not published`) | `detail.cost*` in the catalogs |
| Section order | Verdict, cost, price history, price by platform, facts, neighbourhood, description (DESIGN.md puts the chart before the platform comparison) | `SECTIONS` |
| Panel width | `clamp(440px, 46vw, 640px)` (640 is the mock at 1440px) | `--detail-panel-width` in `index.css` |
| Narrow windows | At 900px and below the panel takes the whole content width and no scrim is drawn. The nav sidebar is hidden at 768px, not at 900px, so between 769px and 900px the panel starts at the sidebar's right edge | `.detail-panel` media rules |
| Stacking | Panel 500, scrim 499: above the nav sidebar, below the compare bar, the toasts and the save dialog | `index.css` |
| `menor custo total` mark | Shown on the deciding Listing only when at least two rent Listings state a stored total and `deciding_rule` is `lowest-complete-total`. Under `lowest-headline-price` no Listing has a total, and beside a single stated total the other Listing's cost is unknown and could be lower, so in both cases the mark would be a claim nobody checked | `MonthlyCostSection.tsx` |
| Header badge on a dual-type Property | The badge of the listing type whose price the header shows (the primary Listing) | `PanelHeader` in `PropertyDetailPanel.tsx` |
| Score cards | Three plain rows, no meter bars | `VerdictSection.tsx` |
| Feature and claim tags | Rectangular tags (7px radius), neutral ink; issues, concerns and risk flags in the amber `health-warn` ink | `.detail-tag` |
| Loading | One muted line `Carregando…`, no spinner | `PanelContent` |
| Facts | The legacy percentile rows are dropped; the z-score rows stay | `FactsSection.tsx` |
| Outbound links | One text link per platform row instead of a button per Listing in the header | `PlatformPricesSection.tsx` |

1. The gate (frontend tier: eslint, build, Playwright e2e, plus the fast tier):
   ```bash
   python scripts/agent/validate.py
   ```
2. While developing:
   ```bash
   python -m pytest src/tests/unit/test_i18n_catalog_parity.py -q -o addopts=
   cd frontend && npx tsc --noEmit -p . && npm run lint
   PLAYWRIGHT_PORT=5238 npx playwright test tests/e2e/property-detail-panel.spec.js
   ```
3. Nothing named after the modal remains:
   ```bash
   grep -rin modal frontend/src frontend/tests   # only aria-modal in CompareView.tsx
   ```
4. By hand, against a running stack:
   - Open Imóveis, scroll down, set a filter, click a card. The panel opens on the right, the grid is dimmed, the nav sidebar is not. Press `Esc`: same scroll position, same filter.
   - Switch to `Mapa`, open a point's `Ver detalhes`. The panel covers the right part of the map, the left part stays usable, no dimming.
   - Open Favoritos, open a favourite, close it. The heading stays `Favoritos`.
   - On a rent Property, `Custo mensal` lists rent, condo, IPTU and the total. A QuintoAndar or OLX Listing with bundled fees shows one `Condomínio + IPTU` row.

## Notes / Follow-ups

- **The panel needs the Story 1.2 API image.** `Custo mensal` reads `listings[].cost`. Against an older API image the section is absent (no error); the rest of the panel works.
- **The legacy `percentile_rank*` fields are still on the wire** (list, batch, detail, export CSV, `docs/api.md`, contract test). No component reads them. Ledger entry DW-47 lists what still does; DW-49 is resolved.
- **Favoritos cards have no badge, so the rule "sentence exactly when the card has a badge" does not hold there.** The Favoritos endpoint does not serve the percentile fields (Story 1.7 note), while the detail endpoint does. A favourite's panel can show a sentence its card has no badge for. Story 5.10 owns the Favoritos columns.
- **Map points do not draw under the Vite dev server in this worktree.** `GET /node_modules/.vite/deps/maplibre-gl-worker.mjs` answers 404, so the GeoJSON point layer never renders; the raster map and the HTML compare markers do. Not caused by this story (`MapView.tsx` and the Vite config are untouched). The map e2e test therefore opens the panel through the router instead of clicking a point. Whether the production build or the primary checkout is affected was not checked.
- **In the map view the panel covers the map's zoom control** (top right of the map) and the initial centre. The left part of the map stays usable; a point under the panel needs a pan.
- **`sanitizeListingUrl` is stricter than the modal's copy.** It accepts a trusted host or its subdomains; the old check (`hostname.endsWith('olx.com.br')`) also accepted a host such as `evilolx.com.br`.
- **The best-price star on the platform rows is gone.** DESIGN.md keeps the star for favourites alone. Rows are still ordered by price within a listing type; the cost section marks the deciding Listing when two stored totals were compared.
- **In the grid view the page under the scrim is dimmed but still reachable with the keyboard.** The panel is not a dialog and nothing is made inert, which is what keeps the map usable in the map view. In the grid view `Shift+Tab` from the panel lands on cards and filters under the scrim, where the focus ring is hard to see. Deferred in the story spec (low).
- **No verdict label in the header.** The mock shows `Excelente negócio`; no verdict field exists yet, so the header starts with the price. The mock's `/mês` suffix and the "sources differ by R$ N" line are not rendered either (one is new microcopy, the other is arithmetic).
- **Catalog keys that already had no caller before this story** (`common.price`, `common.pricePerM2`, `properties.cityOption` and others) are left alone.
- Related: Story 1.2 (cost projection), Story 1.7 (badge and filter), Stories 3.9, 5.9 and 5.8 (sections to add to this panel).
