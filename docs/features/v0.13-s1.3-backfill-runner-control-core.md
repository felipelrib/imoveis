# Backfill runner control core — lease, pause/resume, safe interruption

> Feature branch: `feat/v0.13-s1.3-backfill-runner-control-core` · Story: `v0.13-s1.3` · Status: implemented

## Problem

The Gemma backfill runner (`src/core/backfill_runner.py` + `scripts/dev/backfill_gemma.py`)
had no mutual exclusion, no operator control, and two correctness holes:

1. **Two runners could both work.** The only "is a backfill running?" signal was the
   advisory `backfill:gemma:active` heartbeat, which nothing enforces. Two concurrent
   runs would also both spend the same daily budget: `DailyBudget.try_consume` was a
   non-atomic `hgetall` → `hset`, so interleaved reservations could read the same
   pre-image and overshoot the provider's RPD cap.
2. **Quota exhaustion silently corrupted data.** `GeminiClient.chat_completions` raises
   after exhausting its 429 retries, but `analyze_visuals` / `analyze_text` caught
   *every* exception and returned `condition_score=0.5` / `sentiment_score=0.5`.
   `run_enrichment` persisted that fabricated score and the runner checkpointed the row
   as processed — so a quota-exhausted multi-day run quietly filled the DB with fake
   0.5s that `mode=missing` would never re-queue. Back-off is only meaningful if the
   failure is visible.

There was also no pause/resume/stop primitive for the CLI and story 1.5's admin API to
share, and `_build_client` hardcoded Gemma — a second, unrouted backend-decision path
that ignores story 1.1/1.2's `ai.enrichment_routing` map (AD-13 forbids it).

## Approach

- **Lease, not heartbeat.** `BackfillLease` is a separate *enforcing* key
  (`<prefix>:lease`) holding a per-process token. `acquire()` is `SET key token NX EX
  ttl` (atomic, so exactly one runner wins); `renew()` / `release()` are owner-token
  CAS — atomic Lua `eval` when the injected client exposes it, a token-guarded
  check-then-act otherwise. The TTL (not a shutdown hook) is what recovers the lease
  after a hard kill, so a crash self-heals without operator action. The existing
  `Heartbeat` is untouched — it is the advisory signal `migrate-primary.sh` observes.
- **Control is state + requests, not a queue.** `BackfillControl` writes single request
  keys (`:control:pause`, `:control:stop`) — *levels*, so a second pause is idempotent
  and a runner that starts later still observes an outstanding request — and publishes
  `<prefix>:state` (`idle | running | paused | backing-off`) with a short TTL, so a
  crashed runner reads back as `idle` rather than a stuck `running`. Story 1.5's admin
  endpoints construct the same object against the same keys: one control path, not two.
- **Atomic budget.** `try_consume` does the window roll, the increment, the limit
  check and the rollback in **one Lua script** (`_BUDGET_RESERVE_LUA`) whenever the
  injected client exposes `eval` — a real Redis always does. Rolling the window as a
  separate round-trip (the first cut) let two writers that both saw a stale window
  each stamp `count=0` and wipe the other's reservation. A client without `eval`
  keeps the same sequence as separate ops, documented as the **non-atomic fallback**
  (test doubles only). Either way a reservation that *opened* a window and then failed
  the limit check deletes the key, so no phantom zero-count window is left reporting
  ~24h of `seconds_until_reset`. `consumed` / `remaining` / `seconds_until_reset`
  semantics are unchanged.
- **The lease is renewed inside `run_backfill`, not by the caller's progress hook.**
  `run_backfill` takes an optional `lease` and renews it once per launch-loop
  iteration and once per pause poll. The old design renewed from the CLI's
  `on_progress`, which fired only on *successful* rows, so a storm of failing rows
  could let the 900s lease lapse under a second runner. A `renew()` that returns
  `False` means this process no longer owns the lease — another runner may already be
  working the same queue — so it stops launching, flags `BackfillResult.lease_lost`,
  drains what is in flight, and the CLI exits `7`. `on_progress` now fires in the
  worker's `finally` (success, error *and* quota rows) and is deliberately **not**
  ticked while paused: it beats the advisory `:active` heartbeat, and a paused runner
  that keeps beating it blocks `migrate-primary.sh` — the very thing an operator
  usually pauses for.
- **A provider 429 is not proof the day is spent.** Free tiers throttle per minute
  (RPM/TPM) *and* per day (RPD). `--continuous` used to sleep to the rolling-window
  reset (up to ~24h) on any quota refusal. It now caps that wait at
  `backfill.quota_backoff_seconds` (900) whenever the **local** daily budget still has
  room for another property, and says so in the printed line; a genuinely spent local
  budget still sleeps to the reset.
- **Only two scopes are runnable.** `run_enrichment` always runs visual+sentiment and
  writes a deal verdict only when `stages == "all"`, so a `deal_verdict`-only scope
  would spend cloud quota on visual+sentiment, overwrite `ai_score` and still never
  write a verdict. The CLI refuses it; `stages_for_task_classes` keeps translating
  `verdict_only` because it is a legitimate value of that vocabulary elsewhere (the
  `ai_enrich` task honors it) — the policy belongs at the CLI, not in the core helper.
- **Quota is a distinguished error.** `AIQuotaExhaustedError(AIClientError)` carries
  `is_quota_exhausted = True` and is raised on a terminal 429 / `RESOURCE_EXHAUSTED`
  body. Every fabricated-score fallback re-raises it before falling back; non-quota
  failures keep their template/0.5 behaviour exactly. `run_backfill` classifies such a
  row as *back off*, not *bad row*: no error counted, ledger attempt rolled back, no
  checkpoint advance, no further launches, state `backing-off`.
- **`src/core` stays framework-free.** The quota predicate duck-types the flag
  (`getattr(exc, "is_quota_exhausted", False)`) instead of importing adapters (AD-1).
  Redis, clock, sleep, control and the predicate are all injected.
- **Scope speaks task classes.** The runner and CLI handle `EnrichmentTaskClass` values;
  `stages_for_task_classes()` translates to the legacy `stages` literal at the edge,
  only for `fetch_candidate_rows` / `run_enrichment`. All writes still go through
  `run_enrichment` — second driver, never second writer (AD-10).

Alternatives rejected: a Redis `SETNX` without TTL (a killed runner would block every
future run until an operator cleaned up); reusing the heartbeat as the lock (it is
advisory, observed by `migrate-primary.sh`, and has no owner token); letting the runner
execute local backends when routing says `ollama` (AD-4 requires local work to go
through the `ai` queue and GPU semaphore — it refuses to start instead).

## How to Test

```bash
bash scripts/agent/validate.sh fast     # lint + unit (includes the two new suites)
bash scripts/agent/validate-ai.sh       # AI-client-change gate
grep -nE "^\s*(from|import) (adapters|api)\b" src/core/backfill_runner.py   # must print nothing
```

Manual, against the running stack (`DATABASE_URL` + `REDIS_URL` from `.env.local`):

1. Route the scope to a cloud backend and export the key:
   `ai.enrichment_routing.{visual,sentiment,deal_verdict}: gemma` + `GEMINI_API_KEY`.
2. Pre-flight with `--dry-run`: it now resolves the same routing a real run demands and
   prints `WARNING: this scope would refuse to start a real run: …` when it would not
   start (all-local routing, missing key) — without needing the key and without failing
   the plan.
3. Start a run: `PYTHONPATH=src python scripts/dev/backfill_gemma.py --limit 5`.
4. From a second terminal, `--status` shows `control state: running`, any **pending
   requests**, and the lease holder; starting a second run prints the holder and
   exits `5`.
5. `--pause` → the first run stops launching (state `paused`), already-launched rows
   finish, and the `:active` heartbeat stops being beaten so `migrate-primary.sh` is
   free to run; `--resume` continues (it also clears a pending `--stop`); `--stop`
   (or Ctrl-C once, noticed within `control_poll_seconds` even mid-back-off) drains
   and exits `6`.
6. A run started while a pause/stop is outstanding prints
   `Discarding a pending pause request from a previous run` rather than dropping it
   silently.
7. Refused scope: `--task-classes deal_verdict` exits with an explanation naming the
   two supported scopes.
8. Restart: it resumes from the checkpoint without re-enriching completed rows.

## Notes / Follow-ups

- **Operator-visible change (breaking for the existing workflow).** The cloud backfill
  no longer hardcodes Gemma; it derives its backend from `ai.enrichment_routing` via
  `resolve_enrichment_backend(..., for_backfill=True)`. With the shipped all-local
  default it now **refuses to start**, naming `ai.enrichment_routing.<class>` and
  `GEMINI_API_KEY`. Set `visual`, `sentiment` and `deal_verdict` to `gemma` (or
  `gemini`) before the next backfill. A scope that mixes cloud backends is also refused
  — one run drives one client.
- **New exit codes:** `5` = another runner holds the lease, `6` = an operator stop,
  `7` = the lease was lost mid-run. The spec named only `EXIT_LEASE_HELD`;
  `EXIT_STOPPED` was added because reporting an operator stop as `3` (STALLED) would
  misreport a deliberate, resumable interruption, and `EXIT_LEASE_LOST` because a
  runner that loses its lease must be distinguishable from one that finished — it
  exits to avoid becoming a second writer against a queue someone else now owns.
- **Operator-visible: `--task-classes deal_verdict` is now refused.** It used to be
  accepted and silently do the wrong thing (visual+sentiment ran, `ai_score` was
  overwritten, no verdict was written). Use the default full scope, or
  `visual,sentiment`.
- **Operator-visible: `--resume` now clears a pending `--stop` too.** It previously
  cleared only the pause key while printing "will continue launching rows", so an
  earlier `--stop` still ended the run.
- **Bounded quota back-off** (`backfill.quota_backoff_seconds`, default 900): a
  provider 429 that survives the client's retries no longer parks the runner for the
  whole rolling RPD window when the local daily budget still has headroom — that
  refusal is usually the per-minute limit. Raise it if the account's real ceiling is
  daily and the short back-off just re-hits the 429.
- **Control state stays fresh.** `running` is re-published from the launch loop and
  `backing-off` from the budget sleep, both at an interval below the 120s state-key
  TTL; a live run no longer reads back as `idle` from `--status` (or story 1.5's API).
  The runner also no longer stamps `idle` over a deliberate `backing-off` on its way
  out.
- The runner still has **no local execution mode** (AD-4): local backends belong on the
  `ai` queue behind the GPU semaphore, so a local-routed scope is refused rather than
  executed here.
- `migrate-primary.sh`'s heartbeat check-then-act race stays deferred — closing it needs
  a paired shell change outside this story's scope.
- `EMBEDDING` is now permanently excluded from cloud routing (read/write vector-space
  symmetry) — this closes the item deferred from `spec-1-2`.
- The published `<prefix>:state` key is control state only. Coverage/progress telemetry
  is story 1.4; the admin endpoints and UI that consume this control core are stories
  1.5 / 1.6.
