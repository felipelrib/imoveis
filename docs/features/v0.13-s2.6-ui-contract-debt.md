# UI contract debt — toast anchoring + pt-BR plural agreement

> Feature branch: `bmad-loop/20260813-054802-28e6/2-6-ui-contract-debt` · Story: `v0.13-s2.6` · Status: implemented

## Problem

Two shared-surface defects that every later Epic 2 UI story would have inherited and re-pinned:

1. **Toast anchoring (UX-DR3).** `ToastProvider` anchored its container top-right and appended
   without a ceiling. The DESIGN.md contract is the opposite: bottom-anchored, at most two
   stacked, never covering the filter bar. A burst of API errors therefore walked a growing
   column of toasts down over the Filtros bar — and no e2e spec asserted toast position at all,
   so nothing would have caught it.
2. **pt-BR plural agreement (UX-DR1).** Four catalog keys interpolated a count into a hardcoded
   plural noun (`"{n} imóveis"`, `"{n} favoritos"`, `"{n} selecionados"`, `"{n} quartos"`).
   Since v0.13-s1.6 made pt-BR everyone's default, every user with exactly one result read
   `1 imóveis` / `1 favoritos` / `1 selecionados` / `1 quartos`. Two e2e specs pinned the
   defective string verbatim (`"1 selecionados"`), freezing the bug into the gate.

## Approach

- **Toast container flipped to `bottom: 16` (right offset kept).** The right offset is what keeps
  the stack clear of `.compare-bar` (fixed, `bottom: 24px`, centred, min-width 280) without either
  surface having to know about the other — no coupling of the provider to a page's layout. That
  clearance is **verified at the suite's 1280×720 viewport only**; at narrower widths the centred
  bar and the right-anchored stack can still meet (see Notes / Follow-ups).
- **`MAX_VISIBLE_TOASTS = 2`, newest wins.** `showToast` appends then `.slice(-2)`, so the oldest
  is evicted. Eviction is the only path that drops a toast without going through `removeToast`, so
  a small `useEffect` reconciles `timersRef` against the rendered list and clears any orphaned
  auto-dismiss timer. Keeping the trim inside the state updater pure (it only returns the new
  array) avoids a side effect in a React updater that StrictMode double-invokes.
- **`data-testid` on container and item.** Position and stack depth were unassertable before;
  `toast-container` / `toast` make the contract testable without coupling to copy or colours.
- **Plural split at the call site, not in `t()`.** Each defective key becomes a `…One`/`…Many`
  pair — the idiom the catalog already uses for `modal.listingCountOne`/`listingCountMany` — and
  the call site picks with `n === 1`. The custom `t()` stays a plain `{name}` interpolator: adding
  pluralization rules to it would be a new i18n engine for four strings.
- **Branch on the raw count, render the formatted one.** The Properties header passes
  `formatNumber(total, locale)` as `{n}`; the ternary reads `totalResults` / `favouritesData.total`
  so `1.200 imóveis` still selects the plural form off the raw `1200`.
- **Both halves locked, no new frontend test runner.** The catalog half is locked Python-side
  (`test_i18n_catalog_parity.py`, runs in `validate.sh fast`); the render half stays Playwright's.
  Adding vitest/jest would mean a new dependency plus new gate wiring for two assertions.
- **English keeps identical One/Many values for two pairs** (`{n} selected`, `{n} favourited`) —
  English does not inflect there, but both keys must exist so parity and the call-site ternary
  stay uniform across catalogs.

## How to Test

1. The gate covers both halves:
   ```bash
   bash scripts/agent/validate.sh fast   # catalog parity + verbatim plural pins
   bash scripts/agent/validate.sh all    # + Playwright: toast contract, corrected count pins
   ```
2. Manual (pt-BR default): open `/properties` with a filter that matches exactly one property —
   the header reads `1 imóvel`, not `1 imóveis`. Same for `/favourites` (`1 favorito`) and for a
   single compare selection (`1 selecionado`).
3. Manual (toast): enter Compare mode, select four properties, click a fifth twice, then trigger a
   third *different* toast (a failing CSV export is the easiest). Exactly two toasts render
   bottom-right — the first warning is gone and the export failure is present, which is what
   "newest wins" means — and neither covers the Filtros bar nor the centred compare bar. Do this at
   a maximised window: see the narrow-viewport caveat under Notes / Follow-ups.

## Notes / Follow-ups

- **Deferred — DESIGN toast tokens.** Toasts keep their type-coded translucent colours rather than
  DESIGN's `surface-elevated` + `border-hairline` + `rounded.md` + `0 8px 20px #00000055`. The
  AC named anchoring and stack depth only, and the type-coded inks carry semantics (success /
  error / warning / info) that the DESIGN token block does not address. Worth a follow-up story
  that decides how severity survives a single neutral surface.
- **Deferred — optional `desfazer` action.** DESIGN allows a toast to carry an accent action; no
  current caller has an undoable operation, so the affordance was not built.
- **Deferred — sibling plural keys with the same defect** (tracked as `v0.13-fu12`). Out of this
  story's four, but the same count-into-fixed-plural pattern still ships in
  `dashboard.enrichResultOk` / `enrichResultOkSkipped` (`{n} enfileirados`),
  `dashboard.rerunSkipPhotoGate` (`{n} bloqueados`), and `dashboard.rerunWouldQueue` /
  `rerunQueued` (`{n} imóveis` — currently unreferenced from `frontend/src`, so verify they are
  live before splitting). `dashboard.modelsLoaded` dodges agreement with `modelo(s)` rather than
  splitting. The new `test_i18n_catalog_parity.py` cannot catch these (it pins values; it cannot
  know a noun should agree) — a follow-up should split them the same way.
  Checked and **not** defective, contrary to a first pass of this list: `properties.platformsBadge`
  renders only under `platformCount > 1` (`PropertyCard.tsx:167`), and `operations.throughputLine`
  / `etaLine` already have `throughputOne` / `throughputBelowOne` / `etaOneDay` variants selected in
  `operations/lines.ts`.
- **Spec premise corrected.** `compare-view.spec.js` was listed as carrying a defective pin; it
  asserts only `"2 selecionados"` (L85, L114), which is already-correct plural. It was re-verified,
  not edited.
- **`common.bedsShort*` is locked catalog-side only.** Its sole surface is a maplibre popup opened
  by a GL-layer feature click (`MapView.tsx:246`), not by the HTML markers the map spec drives;
  clicking it in headless chromium needs exact canvas coordinates and would be flaky. The verbatim
  catalog pin plus the call-site ternary is the deliberate coverage choice.
- **Toast/compare-bar separation is geometric, not structural** (tracked as `v0.13-fu13`). They
  stay clear of each other because one is right-offset and the other centred with a bounded width,
  and `toast-contract.spec.js` only proves it at Playwright's default 1280×720. Below roughly
  1100 px the centred bar and a wide toast (the stack is `maxWidth: 380`) can overlap, and since
  toasts sit at `z-index: 9999` with `pointerEvents: 'auto'` an overlapping toast would swallow
  clicks on the compare bar for the 4 s it is up. Two bottom-anchored surfaces sharing one strip is
  a layout decision this story's ACs did not settle, so it is recorded rather than improvised — a
  future full-width bottom bar would collide at every width.
