# v0.14-fu2-maplibre-worker-served — the map draws its property points again

> Feature branch: `fix/v0.14-fu2-maplibre-worker-served` · Story: `v0.14-fu2` · Status: implemented

## Problem

In the map view the basemap drew and no property point ever did (ledger entry DW-53). The points are a
GeoJSON source, which MapLibre tiles in a web worker; raster tiles do not use the worker, which is why the
basemap still showed. Since the maplibre-gl 5 → 6 upgrade (`6b57551e`) the worker script was never loaded:

- Dev server: the browser asked for `/node_modules/.vite/deps/maplibre-gl-worker.mjs` and got 404.
- Production build: `vite build` emitted no worker file. `vite preview` answered
  `/assets/maplibre-gl-worker.mjs` with the SPA fallback (index.html, status 200), which is not a script.

maplibre-gl 6 is ESM-only and, when no worker URL is set, derives one at run time as
`new URL('./maplibre-gl-worker.mjs', import.meta.url)` with a computed file name. A bundler cannot follow
that: Vite's dependency pre-bundle (dev) and the app chunk (build) both move the library and leave the
worker behind. No e2e saw it because `data-map-ready` only says the style loaded.

## Approach

- Use the route the library documents for Vite: import the worker with `?worker&url` and pass it to
  `setWorkerUrl()` before the first map is created. Vite bundles the worker together with the shared chunk
  it imports and returns the URL it is served from, in dev and in the build.
- `worker.format: 'es'` in `vite.config.js`: the library starts the worker as a module worker, and in dev
  the worker file is unbundled ESM, so both modes must emit an ES module (Vite's default is `iife`).
- Rejected: `optimizeDeps.exclude: ['maplibre-gl']` (repairs dev only, the build still emits no worker);
  plain `?url` (copies the worker without the `maplibre-gl-shared.mjs` it imports in 6.1.0); copying files
  into `public/` by hand (unhashed, drifts from the installed version).
- maplibre-gl stays at 6.1.0; no version change was needed.
- The regression test needs no test hook: the property sits at the map's initial centre, and the pointer
  cursor that `MapView` sets on `mouseenter` of the `unclustered-point` layer is fired by MapLibre only for
  a rendered feature.

## How to Test

1. Gate (frontend tier: eslint, vite build, Playwright e2e against the dev server):
   ```bash
   python scripts/agent/validate.py
   ```
2. The spec alone, against the dev server: `npx playwright test map-points-render` in `frontend/`.
3. The production build: `npm run build`, `npx vite preview --port 5232 --strictPort`, then
   `PLAYWRIGHT_BASE_URL=http://localhost:5232 npx playwright test map-points-render`.
4. By hand: open Imóveis → Mapa; coloured points appear, a click opens the popup, "Ver detalhes" opens the
   side panel. In the network tab the worker script answers 200 with a JavaScript content type.

Observed on 2026-10-08 (Chromium): dev serves
`/node_modules/maplibre-gl/dist/maplibre-gl-worker.mjs?worker_file&type=module` (200, `text/javascript`);
the build emits `assets/maplibre-gl-worker-<hash>.js` (469 kB; 200, `text/javascript` under
`vite preview`). In both the point is rendered and the click path opens the panel. On the unfixed code the
spec fails at "no rendered property point under the map centre".

## Notes / Follow-ups

- The gate's e2e runs against the Vite dev server only; the production build was checked by hand as in
  step 3. Nothing runs the e2e against `vite preview` automatically.
- The worker bundle carries its own copy of the code it shares with the main thread (469 kB, loaded only
  when a map is created). maplibre-gl 6.13.0 makes the worker self-contained upstream; the import used
  here keeps working across that change.
- Closes DW-53. The v0.14-fu1 fix (`619f7e23`, map page size) was the other cause of the empty map.
