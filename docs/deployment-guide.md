# Deployment Guide

> Generated by BMad `document-project` (quick scan) on 2026-08-05.

## Deployment model

Local-first, single-host Docker Compose. No cloud deployment target; the "production" environment is the user's own machine (WSL2/Linux) with a local GPU for Ollama.

## Services (docker-compose.yml)

| Service | Image | Role |
|---|---|---|
| `postgres` | built in-repo (PostGIS 17-3.5 + pgvector) | Primary DB (`realestate`, `realestate_test`) |
| `redis` | `redis:7-alpine` | Broker + cache + scheduler state |
| `api` | built (`Dockerfile`) | FastAPI app; **runs Alembic migrations from the image** |
| `worker_scraper` | built | Celery scraper queue |
| `worker_ai` | built | Celery AI-enrichment queue (GPU semaphore) |
| `beat` | built | Celery beat (Redis-backed schedule) |
| `ollama_init` | `curlimages/curl` | Ensures Ollama models present |
| `flaresolverr` | `ghcr.io/flaresolverr/flaresolverr:v3.3.21` | Cloudflare challenge solver for scrapers |

Volumes: `postgres_data`, `redis_data`, `image_store` (never deleted by cleanup tooling).

## Environment

- `.env.local` — ports and credentials; always `docker compose --env-file .env.local` (bare `up` drifts ports and breaks `API_KEY` auth).
- Ollama runs on the host (Windows side in WSL setups), not in compose; `OLLAMA_NUM_PARALLEL` must equal `gpu.semaphore_limit`.

## CI/CD

- `ci.yml` — lint (pre-commit, all files), unit/integration/contract tests, frontend build, SonarCloud (skipped when `SONAR_TOKEN` absent), security scans.
- `nightly.yml` — scheduled jobs (live scraper validation etc.).
- `docs.yml` — MkDocs Material site build/deploy.
- Merges are squash-only via `scripts/agent/finish-feature.sh --pr` after CI green.

## Operational guardrails

- Never `docker system prune` / `volume rm` / `compose down -v` on the primary stack.
- `scripts/agent/docker-cleanup.sh` after feature work: prunes stopped containers, dangling/feature/worktree images, build cache; keeps primary `imoveis-*` images and all named volumes.
- `validate.sh`/`finish-feature.sh` recreate the primary Postgres container — never run concurrently with long DB jobs (backfills/migrations).
