# Development Guide

> Generated by BMad `document-project` (quick scan) on 2026-08-05. Canonical setup reference: [setup.md](setup.md); agent workflow gates: `CLAUDE.md` + `scripts/agent/`.

## Prerequisites

- Python 3.11, Node (frontend), Docker + docker compose
- Local Ollama/LM Studio for AI enrichment (GPU); from WSL: `OLLAMA_HOST=http://$(ip route show default | awk '/default/{print $3}'):11434`
- `.env.local` for ports/credentials (validate scripts derive URLs from it)

## Install & run

```bash
./scripts/setup.sh          # full stack setup
./scripts/start.sh          # start services
pip install -r requirements.txt
(cd frontend && npm install && npm run dev)
```

Compose stack: `postgres` (PostGIS 17-3.5), `redis`, `api`, `worker_ai`, `worker_scraper`, `beat`, `ollama_init`, `flaresolverr`. DBs: `realestate` / `realestate_test`.

## Validation (never raw pytest / npm test)

```bash
bash scripts/agent/validate.sh fast      # lint + unit (<60s)
bash scripts/agent/validate.sh backend   # + integration + contract (rebuild api image first if tests/migrations changed)
bash scripts/agent/validate.sh all       # full CI gate before PR
```

Domain gates: `validate-scrapers.sh --require-live` (scraper changes), `validate-ai.sh` (AI prompt/client changes), contract tests (API schema), `alembic check` (DB schema).

## Branch & finish workflow

```bash
git rev-parse --abbrev-ref HEAD                      # first action every session
bash scripts/agent/setup-branch.sh "<task-slug>"     # if on main
bash scripts/agent/finish-feature.sh --pr            # push, PR, squash-merge, cleanup (long-running)
```

CI (`ci.yml`) runs pre-commit on ALL files (stricter than local flake8 scope), Sonar new-code coverage ~80%, plus nightly jobs. Docs build via `docs.yml` (MkDocs Material).

## Conventions

- Config only through `AppConfig` (`src/infra/config.py`); no `os.getenv` elsewhere; no hardcoded ports/URLs.
- Conventional commits; regression test required with every `fix:`.
- Feature docs: `docs/features/BIN-<id>-<slug>.md` from `_template.md`.
- Testing is risk-tiered: TDD in `core/`, cassettes for scrapers, characterization locks for brownfield SQL, minimal mocks for glue.
