# Harness Troubleshooting

Accumulated gotchas from running the agent workflow (implement → validate → docs → local merge). New gotchas get appended **here**, not inlined into workflow rules. Tool-agnostic: applies the same whether you're running Claude Code or Cursor.

When a retrospect finds a new one-off failure worth remembering, add it to the relevant section below.

## Workspace setup

- **`setup-workspace.sh` argument handling:** don't pass `--help` (or other unknown flags) — the script treats non-flag args as the branch slug and will create a real worktree (e.g. `feat/help`). Read the script header for usage; tear down accidental worktrees with `git worktree remove --force <path>` + `git branch -D`.
- **Already-isolated sessions (native product worktrees):** if the calling product already gave this session its own dedicated worktree before `setup-workspace.sh` ever ran (Claude Code's `EnterWorktree` tool / `Agent` `isolation: "worktree"`, or Cursor's background-agent dispatch), `setup-workspace.sh`/`setup-worktree.sh` detect this (`in_linked_worktree()` in `lib.sh`) and configure ports/`.env.local`/symlinks **in place** rather than creating a second, nested/sibling worktree. Creating a redundant sibling worktree in that case would try to relocate outside the product's own sanctioned worktree root — permission-gated for Claude Code (`"a model-supplied worktree outside .claude/worktrees/"`). Use `--force-branch` if you explicitly want in-place `setup-branch.sh` behavior instead.
- Worktrees symlink the primary `.venv` (via `setup-worktree.sh`). If validate uses system python and fails on `pgvector`/`geoalchemy2`, create or link `.venv` before re-running.
- **`.env.local` + `API_KEY`:** `setup-worktree.sh` writes ports / `COMPOSE_PROJECT_NAME` / `PLAYWRIGHT_PORT` but does **not** copy `API_KEY`. Before `run-services.sh`, seed `API_KEY` from the primary `.env.local` (or `.env.local.example`'s `local-dev-api-key`). Without it, Compose fails with `required variable API_KEY is missing`.

## Implementation

- **FastAPI error mapping (floats / helpers):** raise `HTTPException` only inside the decorated route (with `responses=` for each status). Helpers should raise `ValueError`/`RuntimeError` and let the route map them. Avoid `score == 0.0` float equality; use falsy checks (`not score`) or integer/sentinel comparisons for "missing AI score" semantics.
- **FastAPI `Query()` models:** put all query fields on the Pydantic model. Mixing `Annotated[Model, Query()]` with extra `Query(...)` parameters (or an injected `Depends` next to the model) can make FastAPI treat the model as a required nested object (`422 Field required` on `filters_in`). Prefer `dependencies=[Depends(...)]` on the route when the handler doesn't need the dependency's return value.
- **Pydantic `BeforeValidator` + optional pattern:** don't put `Field(None, pattern=…)` inside `Annotated[..., BeforeValidator(...), Field(...)]`. That yields `TypeError: Unable to apply constraint 'pattern' to supplied value None for schema of type 'function-before'` on export/OpenAPI when the field is omitted. Use `Annotated[Optional[str], BeforeValidator(...)]` and set `Field(None, pattern=…)` on the model attribute instead (BIN-100).
- **Response models vs AI domain:** `condition_score` / `sentiment_score` (and similar AI fields) are floats — typing them as `int` causes `ResponseValidationError` → 500 on enriched rows (BIN-56). Lock with unit tests that `model_validate` projected rows with fractional scores; don't soft-pass contract 500s when the DB schema is ready.
- **Rate-limited route unit tests:** unit runs have no Redis. Bypass `slowapi.extension.Limiter._check_request_limit` (set `request.state.view_rate_limit`) when TestClient-hitting `@limiter.limit` endpoints with mocked DB.
- **`_is_unchanged` / MagicMock fixtures:** when extending `core.dedupe._is_unchanged` with new fields (`address`, `props_json`, `location`, …), update `test_dedupe_noop.py` helpers to set those attributes explicitly. Bare `MagicMock()` invents truthy stand-ins, so identical-looking fixtures fail with `assert False is True`.
- **`react-hooks/set-state-in-effect` + custom hooks (BIN-141):** the ESLint rule only recognizes a call as a "state setter" when it can trace it back to a literal `const [x, setX] = useState(...)` in the same file. If you extract state into a custom hook (e.g. `usePropertiesPagination` returning `{ page, setPage }`) and call the setter inside a `useEffect` that previously had an `eslint-disable-next-line react-hooks/set-state-in-effect` right above it, that disable comment becomes an "unused directive" warning — but the *next* statement in the effect that calls a real local `useState` setter (even indirectly, e.g. through a plain non-memoized helper like `load()`) now picks up the violation instead. Fix by moving/adding the disable comment to whichever line the rule actually flags after the extraction, not by assuming the original placement still applies.

## Validation (`validate.sh`)

- **Primary-stack invariant:** `validate.sh` never touches the primary compose project — DB/Redis come from the ephemeral `<workspace>-test` stack (`test-stack.sh`, docker-assigned ports, throwaway volumes). Stale host `DATABASE_URL`/`REDIS_URL` env vars are harmless for `backend`/`all` (those scopes override them from the test stack); `fast` never opens a DB connection (SQLite unit tests only). Primary `realestate` migration is exclusively `bash scripts/agent/migrate-primary.sh` (refuses while the backfill heartbeat `backfill:gemma:active` is alive; the key self-clears — never delete it manually). After merging a story that adds Alembic migrations, finish-feature reminds you to run it — nothing migrates primary automatically.
- **WSL Playwright libs:** if E2E fails with `libnspr4.so: cannot open shared object file` and `sudo` is unavailable, `apt-get download` the missing libs, extract with `dpkg-deb -x`, and re-run validate with `LD_LIBRARY_PATH` pointing at the extracted `usr/lib/$(uname -m)-linux-gnu`. On newer Ubuntu (e.g. resolute), prefer `t64` package names (`libatk1.0-0t64`, `libcups2t64`, …); non-`t64` names may have "no candidate". Cache under `/tmp/pw-libs` and export `LD_LIBRARY_PATH` for the whole `validate.sh all` / `finish-feature.sh` invocation.
- **Playwright port clash (parallel worktrees):** default E2E port is `5177` (`PLAYWRIGHT_PORT`). If validate fails with `http://localhost:5177 is already used`, export a free port (e.g. `PLAYWRIGHT_PORT=5187`) for that run, or `fuser -k 5177/tcp` if the leftover process is yours.
- **Map / MapLibre e2e:** do not unmount `MapView` (or swap it for a skeleton) while a bbox refetch sets `mapLoading` — remounts drop HTML compare hit targets and flake (BIN-115). Keep the map mounted; use an overlay. For canvas layers, expose `data-testid` HTML Marker hit targets; wait for `data-map-ready="true"` on `map-view` (set on MapView's first `idle`, BIN-189) before asserting selects. Do **not** re-add giant guessed timeouts: MapView re-syncs markers on `idle` if the style is mid-load, so markers appear deterministically — a compare-marker never appearing is a real resync bug (the `isStyleLoaded()` early-return trap fixed in BIN-189), not "environmental flakiness."
- **Host pytest Redis DB:** `validate.sh` forces `REDIS_URL` to logical DB `REDIS_TEST_DB` (default **15**) on the ephemeral stack's Redis. Integration `flushdb` fixtures refuse DB 0 unless `IMOVEIS_ALLOW_PRIMARY_REDIS_WIPE=1` (BIN-117).
- **Alembic vs fresh Postgres race:** ensure-test-db can hit `FATAL: the database system is starting up` right after the test stack comes up, even after a healthcheck pass. Re-run validate once Postgres is fully up; don't treat that transient as a product regression.
- **Playwright checkbox limits:** when UI intentionally blocks checking (e.g. max-4 select), use `locator.click()` not `locator.check()` — `.check()` fails if the controlled input doesn't become checked.
- **Playwright AI / closed-vocab labels:** after risk flags and category codes go through `t()` / `labelRiskFlag`, assert catalog display strings (`Flood zone`, `Slightly Undervalued`), not raw codes (`flood`, `slightly_undervalued`). Playwright `toContainText('flood')` does **not** match `Flood` (BIN-101+).
- **Playwright strict mode / shared labels:** when card chrome starts showing the same strings as filters (e.g. city in `📍 Neighborhood, City`), scope assertions to the control under test (`getByTestId('…-dropdown').getByText(…)`) — bare `getByText('Belo Horizonte')` will match the card and fail strict mode. Same trap when a fixture **title** contains badge/copy under test (BIN-114) — assert via `getByTestId('listings-by-platform').getByText(…)` (or rename the fixture title). Also toast vs activity-log: if the toast string is a substring of a log line (BIN-123), use `getByText(…, { exact: true })` or scope to the toast container.
- **Playwright boot-time admin GETs:** if the SPA calls a new `/admin/*` endpoint on App mount (e.g. locale preference), add a default mock inside `installCommonMocks` (or a shared helper invoked from it). Otherwise suites that seed `sessionStorage` API keys emit Vite `ECONNREFUSED` proxy noise against the worktree API port even when tests still pass.
- **i18n catalog migrations:** keep default-locale (`en`) catalog values byte-identical to existing Playwright `getByText` / role-name asserts — don't "improve" EN copy while migrating. When number/date helpers switch from hardcoded `pt-BR` to the active locale, update e2e digit-grouping asserts (`3.000` → `3,000`) for the default `en` suite; add a separate PT smoke spec for translated chrome (BIN-99+).
- **Add a third locale:** follow [`docs/i18n/add-a-locale.md`](i18n/add-a-locale.md) (catalog → allowlist → synonym maps → AI template **dicts** → semantic lexicon → tests). Prefer `localeLabelKey` / template registries over `if locale ==` / switcher ternaries — `test_locale_registry_hygiene.py` spot-checks the latter.
- **Backgrounded `validate.sh` through a pipe hides the real exit code:** `bash scripts/agent/validate.sh all 2>&1 | tail -N` run via `run_in_background` reports the completion notification's exit code from `tail` (always 0), not from `validate.sh` — a genuine `rc=1` can look like a clean pass until you actually read the tail of the log. Redirect straight to a file instead (`bash scripts/agent/validate.sh all > log 2>&1; echo "EXIT=$?"`, or run synchronously) whenever the true exit code matters, and always grep the tail for `VALIDATION PASSED`/`VALIDATION FAILED` rather than trusting the notification alone (BIN-147).
- **Strict lint hooks now run locally:** `validate.sh` runs `pre-commit run --all-files` (all git-tracked files, not just `src/` — includes `check-json`, `end-of-file-fixer`, isort/flake8 on `alembic/` and `scripts/`; vendored `.agents/`/`_bmad/` are style-excluded, `_bmad/custom/` and safety hooks are not). Two traps: (1) fixer hooks **modify files** when they fail — commit the auto-fixes and re-run, never `git checkout --` them away; (2) pre-commit only sees **tracked** files — `git add` new files before expecting lint to cover them. Keep `.json` files (including `tsconfig.json`) comment-free — `check-json` is strict `json.load`, no `/* */` or `//`. Single-line HTML cassettes under `src/tests/fixtures/` must end with a trailing newline or `end-of-file-fixer` fails while flake8 is green.

## Dependency audit (`audit-deps.sh`)

- **Advisory by construction:** the audit runs as the last stage of `validate.sh all` (never `fast`/`backend`) and can never fail the gate — `run_audit` reports through `ok`/`warn` and never touches `rc`, so a run with advisories still ends in `VALIDATION PASSED`. If you ever see the audit turn a gate red, that is the regression, not the advisory.
- **Skips are loud, never silent:** a missing `pip-audit`, a missing `frontend/package-lock.json`, or an unreachable network all print a `[WARN] … — skipping` line and exit 0. A degraded source shows as `skipped` (never `0`) in the summary, followed by a `[WARN] DEGRADED RUN: dependencies were NOT fully audited` line — emitted **even when the other source found advisories**, so a partial run can never read as complete. `skipped` is not `0`: re-run with network before treating it as clean.
- **A count of `0` means "audited and clean", never "did not audit".** `pip-audit` stamps `skip_reason` on packages it cannot resolve, and those are not audited. A *partial* skip still yields a count plus a loud `note: N package(s) skipped by pip-audit — not audited`; but when **nothing** was audited the count would legitimately be `0`, so that case is reported as `… audit resolved no auditable packages — skipping (NOT a clean result)` and degrades the run instead. Both sources check it: pip via every package carrying `skip_reason` (or an empty resolution), npm via `metadata.dependencies` resolving to zero packages — `metadata.vulnerabilities.total` alone cannot tell an empty lockfile from a clean one. A green `0` over a tree nobody looked at is the one failure mode this stage exists to prevent.
- **`npm` findings name their packages:** each is printed as `pkg (severity, DIRECT dependency|transitive) — fix: …`, under the severity histogram. `isDirect` is the triage signal — a high-severity **direct** dependency ships in the browser bundle, while a transitive dev-toolchain advisory usually does not. The counts cover dev *and* runtime deps undifferentiated (`npm audit` runs without `--omit=dev`), so they are not a prod/dev split.
- **The stage's own summary is the verdict:** `run_audit` deliberately has no trailing `&& ok …`. Since the script always exits 0 in default mode, a trailing `ok` would print a green "audit complete" for a run that audited nothing. Read the summary line, not a stage banner.
- **Every network call is bounded** by `$AUDIT_TIMEOUT` (default 180s, `--kill-after=30` so a tool ignoring SIGTERM cannot outlive it) — a stalled registry degrades to a skip instead of hanging `validate.sh all`, and therefore `finish-feature.sh`, forever. Tune it as whole seconds or a coreutils duration (`AUDIT_TIMEOUT=30`, `30s`, `2m`). Caveats the script announces rather than hides: a malformed **or zero** value falls back to 180 with a `[WARN] invalid AUDIT_TIMEOUT` (a non-numeric value would make every call exit 125 and blame the network, and coreutils reads `timeout 0` as *no limit* — the one value that would void the bound), and on a host with no usable `timeout` the calls run **unbounded** behind a `[WARN] no usable timeout — audit calls run UNBOUNDED`. That probe happens once at startup, not inside the tool call: `warn` writes to **stdout** and the tool call is a command substitution, so warning from inside it would be captured into the JSON and turn every audit into a false "offline" skip.
- **"Timed out" and "offline" are different skip lines.** A tool killed by the bound (exit 124, or 137 after `--kill-after`) reports `… audit timed out after N — skipping (raise AUDIT_TIMEOUT if the link is slow)`, not the offline message. The distinction matters because the natural reaction to a bogus "offline" is to *lower* `AUDIT_TIMEOUT`, which would disable the audit permanently.
- **The audit is skipped once the gate is already red:** `run_audit` short-circuits when `rc != 0` (a read, never an assignment) — no point spending minutes of network on a run whose verdict is already `VALIDATION FAILED`. Fix the failure and re-run to see the audit.
- **`validate.sh all` now talks to the network on the merge path.** `pip-audit` queries PyPI/OSV and `npm audit` sends the dependency tree to the registry, on every full gate run and therefore every `finish-feature.sh`. Offline merges still work — they just always print a degraded run.
- **Exit codes lie, JSON doesn't:** both `pip-audit` and `npm audit` exit non-zero for "vulnerabilities found" as well as for "tool/network failure". The script distinguishes the two solely by whether the JSON parses (`--format json` / `--json`) — never re-plumb it to scrape human output or trust `$?`.
- **`pip-audit` lives in `setup-tools.sh`, not `requirements.in`:** `requirements.txt` is the pip-compile'd **runtime** lockfile that builds the API image, so a gate-only audit tool must not be added there (it would ship to production and need a network `pip-compile` regeneration). `PYTHON_TOOLS` in `setup-tools.sh` is where every other gate-only tool is declared, and `validate.sh` sources it.
- **Bump, don't mute:** resolve a real finding with a deliberate dependency bump revalidated through `validate.sh all` (Dependabot bumps follow the same local-validation path). Never add `.trivyignore`-style suppressions, `--audit-level` softening, or a skip flag to silence the tool.
- **Operator strict run:** `bash scripts/agent/audit-deps.sh --strict` exits 1 when findings exist **or when either audit degraded** — a security check that cannot tell "clean" from "did not run" is worse than none. For deliberate checks only; `validate.sh` must never pass `--strict`, and a unit test (`src/tests/unit/test_audit_deps_gate.py`) locks that.
- **Scope caveat — this is dependency scanning only.** The retired CI also ran a Trivy *filesystem/base-image* scan; that coverage is still gone (`.trivyignore` remains as history). `audit-deps.sh` audits `requirements.txt` and `frontend/package-lock.json`, nothing else — container/OS-package CVEs are unscanned.
- **Stubbing for tests/offline debugging:** `PIP_AUDIT_BIN` / `NPM_BIN` override the resolved binaries (`PIP_AUDIT_BIN=/bin/false NPM_BIN=/bin/false bash scripts/agent/audit-deps.sh` reproduces the fully degraded path without a network). They are honoured in real runs too, and `validate.sh` sources `.env.local` with `set -a` — so an override announces itself with a `[WARN] … override active` line. If you see one during a normal gate run, the audit is not running the tools you think it is.

## Feature docs & migrations

- **YAML `extra` shape changes:** when nesting keys (e.g. `extra.cities[].neighborhoods` replacing top-level `neighborhoods`), grep consumers beyond the scraper `__init__` — Celery helpers (`_olx_neighborhood_catalog`), seed-coverage tests, and any `extra.get("neighborhoods")` readers — or BH fan-out slugs silently vanish.
- **Live Ollama goldens** (`test_ai_quality` sentiment) are `@pytest.mark.slow` and excluded from `validate.sh` unit via `-m "not slow"`. Run them with `bash scripts/agent/validate-ai.sh` (120s timeout) after prompt/client changes — don't rely on the 30s unit gate.
- **Soft-reset squash trap:** never `git reset --soft origin/main` then recommit if the feature branch is behind a moved `main` while your tree is still based on an older tip — the resulting commit can **delete** sibling branches' files already on `main`. Prefer `git fetch origin main && git rebase origin/main` (or merge) then a normal fixup commit; only soft-reset onto `origin/main` when the index already contains those newer main files.
- **Soft-reset staging trap:** `git reset --soft` (to `HEAD~N` or `origin/main`) leaves **every** changed file already staged. A subsequent `git add <one-file>` is additive-only — it does **not** unstage the rest — so `git add docs/...md && git commit` silently commits everything. Run `git reset HEAD -- .` (full unstage) immediately after the soft-reset, *then* `git add` selectively per intended commit (BIN-150).
- **Squash-merge commit title:** `finish-feature.sh` titles the squash commit from the branch's `git log -1` (HEAD). If the last commit is a `docs:` fixup, the merge lands with a weak title. Prefer keeping the `feat:`/`fix:` implementation commit as HEAD (commit docs first), or amend the message when prompted — don't hard-reset published history to fix a title.
- **Alembic revision IDs:** never reuse a `revision` string already on `origin/main` (BIN-82 collided with BIN-84 on `d1e2f3a4b5c6`). Before writing a migration, `git fetch origin main && git ls-tree -r --name-only origin/main alembic/versions/` and grep the proposed id. Prefer opaque random hex over sequential-looking ids.
- **Alembic multi-head race (parallel branches):** two feature branches that both set `down_revision` to the same then-HEAD produce `Multiple head revisions` once both land on `main` (BIN-118 vs BIN-121). Before finish / after merging `main` into the feature branch, run `alembic heads` (or `PYTHONPATH=src .venv/bin/alembic heads`) and ensure a **single** head — re-point your migration's `down_revision` at the new main tip if needed.
- **`EnterWorktree` unavailable to background-job sessions at repo root:** a session launched at the primary checkout root (not itself an `Agent isolation:"worktree"` subagent) gets `Cannot enter worktree: ... switching is only available to sessions whose working directory is inside a worktree` when calling `EnterWorktree` with `path` on an existing worktree — even though the tool description says this should work. Fall back to plain `cd <worktree-path>` via Bash; it behaves identically for git/validate/finish purposes and, unlike a true harness-native subagent worktree, survives `teardown.sh --remove` deleting the directory — the next Bash call's `pwd` lands back on the primary checkout instead of the tool going permanently dead.
- **Dirty tree vs finish:** `finish-feature.sh` refuses a dirty working tree. Parallel agents often leave unrelated edits (ADR/scripts). Stash **only** those unrelated paths before finish; never stash or discard your feature commits. A parallel `setup-worktree.sh` run may also leave an untracked tool-harness symlink (`.claude` or `.cursor`) if it isn't gitignored in that checkout — remove it or confirm it's ignored, since porcelain dirtiness blocks finish.
- **Playwright query-string asserts:** `URLSearchParams` encodes spaces as `+`. When polling captured request URLs, use `decodeURIComponent(url.replace(/\+/g, ' '))` before substring checks on filter values with spaces/accents.
- **Playwright Scraper Control:** `installCommonMocks` does **not** mock `GET /platforms`. Tests that assert platform `<option>` labels must call `mockPlatforms(page)` (see `frontend/tests/e2e/helpers/apiMocks.js`) or the select stays on "Loading platforms…".

## Scrapers (`validate-scrapers.sh`)

- **Cloudflare / proxy on live dry-run (BIN-127+):** QuintoAndar remains the required live probe. Additional platforms (e.g. ZapImóveis) may soft-skip on HTTP 403/429 after QA passes — treat as environmental, not a parse regression. Fail the gate when HTTP 200 succeeds but extract/normalize yields zero listings (cassettes outdated). Prefer cassette unit tests as the offline parse lock.
- **Price-funnel bisect without working price filters:** if search pages ignore `precoMinimo`/`precoMaximo` (or equivalent), bisecting saturates into thousands of identical windows. Guard with an in-band price majority check before enqueueing halves (see `ZapImoveisScraper._price_filter_effective`).

## Cleanup / Compose

- **Fail-closed teardown:** `teardown.sh` reads the compose project from `.env.local` only (inherited env is never trusted for destruction) and refuses when the identity is missing or resolves to the primary project. `--primary` is an explicit operator override that stops primary containers; primary volumes are **never** wiped by the script. If teardown refuses, fix `.env.local` — never bypass with raw `docker compose down`.
- **Stale worktree env in the shell:** after `teardown.sh --remove` (or after sourcing a worktree `.env.local`), `unset COMPOSE_PROJECT_NAME POSTGRES_PORT REDIS_PORT API_PORT FRONTEND_PORT PLAYWRIGHT_PORT` before running `docker compose` on the primary — otherwise Compose recreates `feat-*` projects against busy ports and can look like the primary stack vanished.
- Never run `teardown.sh --remove` from the primary checkout expecting worktree removal — run it from the worktree (or pass the worktree path explicitly).
- **Finish teardown can't remove its own subagent worktree:** when running inside a session that was itself given an isolated worktree by the harness (`Agent` tool `isolation: "worktree"` / `EnterWorktree`), the worktree is `locked` at the git level for that session. `finish-feature.sh`'s `teardown.sh --remove` step still stops/removes Compose containers, volumes, and local images correctly, but the final `git worktree remove` warns `could not remove worktree (uncommitted changes? use with care)` and leaves the directory + branch on disk — this is the lock, not actual uncommitted work (verify with `git status --short` inside the worktree). There is no in-session fix: after confirming the merge landed and the tree is clean, report the leftover path/branch in the wrap-up and let the parent/orchestrating session (or a human) run `git worktree remove <path> --force && git branch -D <branch>` from the primary checkout. Two corollaries (observed BIN-141): (1) `Read` on an absolute primary-checkout path works from inside the locked subagent worktree, but `Edit`/`Write` on that same primary path is refused — either edit your own worktree's copy and land it via a normal commit, or hand the change to the orchestrator as text. (2) Bash also refuses `cd <primary> && git ...` in one call — verify a merge landed with `git fetch origin main && git log origin/main` run from inside your own worktree, no cd needed.
- **Successful self-teardown kills the subagent's own tools:** if `finish-feature.sh`'s `teardown.sh --remove` *does* successfully remove the isolated worktree a subagent is running in, that subagent's Bash/Edit/Write tools go permanently dead for the rest of its session — there is no fallback to the primary checkout, and `ExitWorktree`/`EnterWorktree` are unavailable to a cwd-pinned subagent (observed BIN-134). Sequence wrap-up accordingly: any step that needs the filesystem — including sprint-status.yaml/epic-completion updates, which are file edits (ADR 0005) — must happen *before* the teardown; treat any further file-editing step as something to hand off as text in the final report.

## Domain validation hooks (scraper / AI / DB / API)

The "after you change X, run gate Y" hooks live in `CLAUDE.md` § Domain validation hooks (always-on). The incident-derived gotchas behind them are recorded here:

- **Mass scrape `0 processed / N errors` with successful HTTP:** check `AppConfig` still exposes every YAML section `tasks.scrape_listings` reads (e.g. `cfg.dedup`) and worker logs for `scrape_persist_error` / `AttributeError`. Rebuild `worker_scraper` after config/scraper fixes.
- **OLX `olx_no_listing_payload` / missing `__NEXT_DATA__`:** parse Flight (`__next_f.push`) ads; intermittent Cloudflare 403 is environmental (proxy pool), not a parse regression.
- **OLX detail URLs often omit `/venda|/aluguel`:** stamp `_olx_listing_type` from the search window and prefer path segments (not substring `venda`, which matches `venda-nova`). `locationDetails` is often the **seller/region**, not the property: run `core.olx_location` reconcile before geo allowlist; backfill with `scripts/dev/fix_olx_listings.py`.
- **Never recreate the API with bare `docker compose up`:** always `compose_cmd` / `./scripts/start.sh` / `--env-file .env.local`. Empty `API_KEY` makes SPA admin calls (`/admin/schedule`, recalculate, …) return **403 Admin API key not configured**.
- **Celery beat tasks must be in `task_routes`** for a queue workers consume (`scrapers` or `ai`). Unrouted tasks land on default `celery` and never run (BIN-76: empty Dashboard `/system/pipeline/history`). After adding a beat entry, assert the route in `test_schedule.py` and rebuild `beat` + the consuming worker.
- **Properties `max_price` must filter `property_listings` by `price_type`** (`rent`|`sale`), not decisioning `p.price` (lowest listing, rent-preferred) — otherwise sale budgets match dual-listed homes on cheap rent (BIN-77). Hide number steppers on typed amount inputs (`type="text"` + `inputMode="numeric"`; CSS alone is not enough — BIN-79).
- **API image does not bind-mount `src/`:** after `src/api/` filter/route changes, `docker compose --env-file .env.local build api && docker compose --env-file .env.local up -d api` before trusting local UI against Docker (BIN-79 stale-image miss). This is a **run-the-app** concern — validation itself never rebuilds or restarts primary services.
- **Deep links use sequential `public_id` in URLs; UUID remains the PK.** Any endpoint that stores `property_id` (favourites, watchlist, …) must resolve via `api.property_refs.resolve_property_uuid` — digit-only refs are `public_id`, not UUID (BIN-82 / #85 UUID cast 500).
