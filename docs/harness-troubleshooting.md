# Harness Troubleshooting

Accumulated gotchas from running the agent workflow (implement → validate → docs → local merge). New gotchas get appended **here**, not inlined into workflow rules. Tool-agnostic: applies the same whether you're running Claude Code or Cursor.

When a retrospect finds a new one-off failure worth remembering, add it to the relevant section below.

## Native Windows migration (2026-10-01)

- Before a `frontend` or `full` tier run of `validate.py` (or `ship.py`), stop Vite
  processes using this checkout. Windows locks loaded native Rolldown modules;
  `npm ci` then fails with EPERM and leaves dependencies incomplete. Stop only the
  identified dev process, re-run `npm ci --prefix frontend`, and restart Vite
  after finishing.
- A Windows virtualenv executable may launch a separate base-interpreter process.
  The supervisor records the real process PID, which can differ from the launcher
  PID returned by `Popen` or Task Scheduler. Verify identity against the child
  process command line; ownership depends on the OS file lock, not a stale PID.
- The gate itself is `python scripts/agent/validate.py` and needs no Git Bash.
  For the remaining shell scripts (`migrate-primary.sh`, `scripts/ops/*.sh`),
  invoke Git Bash by its full path from PowerShell: Windows subprocess lookup can
  select `C:\Windows\System32\bash.exe` (the WSL launcher) even when a parent Git
  Bash shell selected the right tools. Shell regression fixtures resolve the
  executable explicitly.
- Windows virtualenvs use `.venv/Scripts/python.exe`; `uvloop` is Linux-only.
  Install the generated Windows lock with Python 3.11. WindowsApps aliases are
  not proof of a runnable Python. Gate helpers capability-check the interpreter.
- Git reports drive paths while MSYS reports `/c/...`. Compare canonical Git
  roots, and pass native Python module paths separated by `;` on Windows.
  `.gitattributes` pins shell files to LF. Keep `.env.local` LF too for scripts
  that source it. The native supervisor loads dotenv literally without expansion.
- `chmod 000` does not make a normal NTFS file unreadable. The allowlist failure
  fixture simulates the failed readability probe in the same shell and still
  asserts that no values were applied; production handling is unchanged.
- Docker Desktop failed here on inaccessible AF_UNIX reparse entries in both
  `%LOCALAPPDATA%\Docker\run` and `%LOCALAPPDATA%\docker-secrets-engine`.
  With Desktop stopped, preserving those two runtime directories under dated
  names and creating fresh directories allowed startup. This was a local repair,
  not a general instruction to delete Docker state. Settings, VHDX, containers
  and named volumes were retained. Do not factory-reset or purge data to clear
  a socket error. [Docker troubleshooting](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/)
  describes diagnostics and the destructive scope of its reset options.

## Workspace setup

- **Branching is plain git:** `git switch -c feat/<slug>` (story-key branches `feat/v0.14-s1.2-…` drive `ship.py`'s feature-doc check). There is no branch/worktree script any more; parallel work uses bmad-loop's own worktrees or Claude Code's native `--worktree`. The ephemeral test stack of a linked worktree gets its own compose project (`<COMPOSE_PROJECT_NAME>-test-<hash>`), so two checkouts can validate concurrently without a port registry.
- **Validation needs the project `.venv`:** run the gate with the venv interpreter (`.venv/Scripts/python.exe scripts/agent/validate.py` on Windows, `.venv/bin/python` on Linux). If it runs on system python it fails on `pgvector`/`geoalchemy2` imports — create the venv before re-running; the `validate.sh` wrapper activates it for you.

## Implementation

- **FastAPI error mapping (floats / helpers):** raise `HTTPException` only inside the decorated route (with `responses=` for each status). Helpers should raise `ValueError`/`RuntimeError` and let the route map them. Avoid `score == 0.0` float equality; use falsy checks (`not score`) or integer/sentinel comparisons for "missing AI score" semantics.
- **FastAPI `Query()` models:** put all query fields on the Pydantic model. Mixing `Annotated[Model, Query()]` with extra `Query(...)` parameters (or an injected `Depends` next to the model) can make FastAPI treat the model as a required nested object (`422 Field required` on `filters_in`). Prefer `dependencies=[Depends(...)]` on the route when the handler doesn't need the dependency's return value.
- **Pydantic `BeforeValidator` + optional pattern:** don't put `Field(None, pattern=…)` inside `Annotated[..., BeforeValidator(...), Field(...)]`. That yields `TypeError: Unable to apply constraint 'pattern' to supplied value None for schema of type 'function-before'` on export/OpenAPI when the field is omitted. Use `Annotated[Optional[str], BeforeValidator(...)]` and set `Field(None, pattern=…)` on the model attribute instead (BIN-100).
- **Response models vs AI domain:** `condition_score` / `sentiment_score` (and similar AI fields) are floats — typing them as `int` causes `ResponseValidationError` → 500 on enriched rows (BIN-56). Lock with unit tests that `model_validate` projected rows with fractional scores; don't soft-pass contract 500s when the DB schema is ready.
- **Rate-limited route unit tests:** unit runs have no Redis. Bypass `slowapi.extension.Limiter._check_request_limit` (set `request.state.view_rate_limit`) when TestClient-hitting `@limiter.limit` endpoints with mocked DB.
- **`_is_unchanged` / MagicMock fixtures:** when extending `core.dedupe._is_unchanged` with new fields (`address`, `props_json`, `location`, …), update `test_dedupe_noop.py` helpers to set those attributes explicitly. Bare `MagicMock()` invents truthy stand-ins, so identical-looking fixtures fail with `assert False is True`.
- **`react-hooks/set-state-in-effect` + custom hooks (BIN-141):** the ESLint rule only recognizes a call as a "state setter" when it can trace it back to a literal `const [x, setX] = useState(...)` in the same file. If you extract state into a custom hook (e.g. `usePropertiesPagination` returning `{ page, setPage }`) and call the setter inside a `useEffect` that previously had an `eslint-disable-next-line react-hooks/set-state-in-effect` right above it, that disable comment becomes an "unused directive" warning — but the *next* statement in the effect that calls a real local `useState` setter (even indirectly, e.g. through a plain non-memoized helper like `load()`) now picks up the violation instead. Fix by moving/adding the disable comment to whichever line the rule actually flags after the extraction, not by assuming the original placement still applies.

## Validation (`validate.py`)

- **Tier comes from the diff:** `python scripts/agent/validate.py` picks `docs` | `fast` | `frontend` | `backend` | `full` from the changed paths (`--required-tier` prints it, `--tier X` forces one). Scraper, AI prompt/client and `scripts/`/harness changes bolt on their domain gate (`--only scrapers|ai|harness` runs one by itself). On the Windows host the `fast` tier is ≈ 75 s (lint 17 s + unit 55 s) and `docs` ≈ 11 s; the `harness`-marked tests (script spawns) are ≈ 14 min serial and run only when scripts change or in the `full` tier.
- **Primary-stack invariant:** `validate.py` never touches the primary compose project — DB/Redis come from the ephemeral `<workspace>-test` stack it builds from `docker-compose.test.yml` (docker-assigned ports, throwaway volumes; `--down` tears it down). Stale host `DATABASE_URL`/`REDIS_URL` env vars are harmless for `backend`/`full` (those tiers override them from the test stack); `fast` never opens a DB connection (SQLite unit tests only). Primary `realestate` migration is exclusively `bash scripts/agent/migrate-primary.sh` (refuses while the backfill heartbeat `backfill:gemma:active` is alive; the key self-clears — never delete it manually). After shipping a branch that adds Alembic migrations, `ship.py` reminds you to run it — nothing migrates primary automatically.
- **Stamp, not exit code, is what the push guard reads:** a green run on a **clean** tree writes `.run/validated/<tree-sha>.<tier>` in the primary checkout; a dirty tree gets `[WARN] … no validation stamp written`. `.claude/hooks/guard.py` denies `git push` to `main` unless HEAD's tree carries a stamp for at least the required tier (`validate.py --check-stamp` shows `required=… have=…`). "It passed but push is denied" therefore means: you validated before the last commit, or on a dirty tree — commit, re-run, push.
- **WSL Playwright libs:** if E2E fails with `libnspr4.so: cannot open shared object file` and `sudo` is unavailable, `apt-get download` the missing libs, extract with `dpkg-deb -x`, and re-run validate with `LD_LIBRARY_PATH` pointing at the extracted `usr/lib/$(uname -m)-linux-gnu`. On newer Ubuntu (e.g. resolute), prefer `t64` package names (`libatk1.0-0t64`, `libcups2t64`, …); non-`t64` names may have "no candidate". Cache under `/tmp/pw-libs` and export `LD_LIBRARY_PATH` for the whole `validate.py` invocation.
- **Playwright port:** the E2E port is `PLAYWRIGHT_PORT` when set, otherwise `validate.py` probes a free one in 5177–5299. If a run still fails with `http://localhost:<port> is already used`, the leftover process is yours — kill it or export another port for that run.
- **Map / MapLibre e2e:** do not unmount `MapView` (or swap it for a skeleton) while a bbox refetch sets `mapLoading` — remounts drop HTML compare hit targets and flake (BIN-115). Keep the map mounted; use an overlay. For canvas layers, expose `data-testid` HTML Marker hit targets; wait for `data-map-ready="true"` on `map-view` (set on MapView's first `idle`, BIN-189) before asserting selects. Do **not** re-add giant guessed timeouts: MapView re-syncs markers on `idle` if the style is mid-load, so markers appear deterministically — a compare-marker never appearing is a real resync bug (the `isStyleLoaded()` early-return trap fixed in BIN-189), not "environmental flakiness."
- **Host pytest Redis DB:** `validate.py` forces `REDIS_URL` to logical DB `REDIS_TEST_DB` (default **15**) on the ephemeral stack's Redis. Integration `flushdb` fixtures refuse DB 0 unless `IMOVEIS_ALLOW_PRIMARY_REDIS_WIPE=1` (BIN-117).
- **Alembic vs fresh Postgres race:** the test-DB bootstrap can hit `FATAL: the database system is starting up` right after the test stack comes up, even after a healthcheck pass. Re-run validate once Postgres is fully up; don't treat that transient as a product regression.
- **Playwright checkbox limits:** when UI intentionally blocks checking (e.g. max-4 select), use `locator.click()` not `locator.check()` — `.check()` fails if the controlled input doesn't become checked.
- **Playwright AI / closed-vocab labels:** after risk flags and category codes go through `t()` / `labelRiskFlag`, assert catalog display strings (`Flood zone`, `Slightly Undervalued`), not raw codes (`flood`, `slightly_undervalued`). Playwright `toContainText('flood')` does **not** match `Flood` (BIN-101+).
- **Playwright strict mode / shared labels:** when card chrome starts showing the same strings as filters (e.g. city in `📍 Neighborhood, City`), scope assertions to the control under test (`getByTestId('…-dropdown').getByText(…)`) — bare `getByText('Belo Horizonte')` will match the card and fail strict mode. Same trap when a fixture **title** contains badge/copy under test (BIN-114) — assert via `getByTestId('listings-by-platform').getByText(…)` (or rename the fixture title). Also toast vs activity-log: if the toast string is a substring of a log line (BIN-123), use `getByText(…, { exact: true })` or scope to the toast container.
- **Playwright boot-time admin GETs:** if the SPA calls a new `/admin/*` endpoint on App mount (e.g. locale preference), add a default mock inside `installCommonMocks` (or a shared helper invoked from it). Otherwise suites that seed `sessionStorage` API keys emit Vite `ECONNREFUSED` proxy noise against the configured API port even when tests still pass.
- **i18n catalog migrations:** keep default-locale (`en`) catalog values byte-identical to existing Playwright `getByText` / role-name asserts — don't "improve" EN copy while migrating. When number/date helpers switch from hardcoded `pt-BR` to the active locale, update e2e digit-grouping asserts (`3.000` → `3,000`) for the default `en` suite; add a separate PT smoke spec for translated chrome (BIN-99+).
- **Add a third locale:** follow [`docs/i18n/add-a-locale.md`](i18n/add-a-locale.md) (catalog → allowlist → synonym maps → AI template **dicts** → semantic lexicon → tests). Prefer `localeLabelKey` / template registries over `if locale ==` / switcher ternaries — `test_locale_registry_hygiene.py` spot-checks the latter.
- **Backgrounded gate through a pipe hides the real exit code:** `python scripts/agent/validate.py 2>&1 | tail -N` run via `run_in_background` reports the completion notification's exit code from `tail` (always 0), not from the gate — a genuine `rc=1` can look like a clean pass until you read the tail of the log (BIN-147). `validate.py` ends with a `VALIDATION PASSED (tier=…)` / `VALIDATION FAILED` verdict and, on a pass, a `validation stamp <tree-sha>.<tier>` line — grep for those (or run `validate.py --check-stamp`) rather than trusting the notification; the push guard reads the stamp, not your reading of the log.
- **Strict lint hooks now run locally:** `validate.py` runs `pre-commit run --all-files` (all git-tracked files, not just `src/` — includes `check-json`, `end-of-file-fixer`, isort/flake8 on `alembic/` and `scripts/`; vendored `.agents/`/`_bmad/` are style-excluded, `_bmad/custom/` and safety hooks are not). The same hooks run on every `git commit` once `pre-commit install` has been run (there is no pre-push stage any more). Two traps: (1) fixer hooks **modify files** when they fail — commit the auto-fixes and re-run, never `git checkout --` them away; (2) pre-commit only sees **tracked** files — `git add` new files before expecting lint to cover them. Keep `.json` files (including `tsconfig.json`) comment-free — `check-json` is strict `json.load`, no `/* */` or `//`. Single-line HTML cassettes under `src/tests/fixtures/` must end with a trailing newline or `end-of-file-fixer` fails while flake8 is green.
- **The gate does not depend on the caller's shell (Windows):** from PowerShell a bare `bash` is the WSL launcher (`System32` leads `PATH`) and Git for Windows' `grep -P` refuses a non-UTF-8 locale. `validate.py` therefore puts Git Bash and its own interpreter first on `PATH` for its children, `tests/shell_helpers.py` locates Git Bash from `git` itself, and the four local pre-commit hooks (`forbid-hardcoded-secrets`, `forbid-only`, `forbid-print`, `forbid-fstring-sql`) run `python scripts/agent/lint_forbidden.py <check>` — no bash, no grep. Never turn one back into `bash -c '! grep …'`: a grep that errors made those hooks pass with nothing checked (2026-10-07). A plain `git commit` needs some `python` on `PATH` for these hooks; the script is stdlib-only, so any Python 3 does.

## Dependency audit (`scripts/ops/audit-deps.sh`)

- **Not in the merge path:** the audit is an operator task under `scripts/ops/` and the `audit` job of the nightly GitHub workflow — `validate.py` never runs it, so a dependency advisory can never turn the gate red. Run it by hand (`bash scripts/ops/audit-deps.sh`) when the nightly reports findings or before a deliberate bump.
- **Advisory by construction:** default mode always exits 0 — findings, missing tools and an unreachable network are reported, never fatal, and `run_audit` has no trailing `&& ok …` because a green stage banner for a run that audited nothing would be a lie. Read the summary line, not a stage banner.
- **Skips are loud, never silent:** a missing `pip-audit`, a missing `frontend/package-lock.json`, or an unreachable network all print a `[WARN] … — skipping` line and exit 0. A degraded source shows as `skipped` (never `0`) in the summary, followed by a `[WARN] DEGRADED RUN: dependencies were NOT fully audited` line — emitted **even when the other source found advisories**, so a partial run can never read as complete. `skipped` is not `0`: re-run with network before treating it as clean.
- **A count of `0` means "audited and clean", never "did not audit".** `pip-audit` stamps `skip_reason` on packages it cannot resolve, and those are not audited. A *partial* skip still yields a count plus a loud `note: N package(s) skipped by pip-audit — not audited`; but when **nothing** was audited the count would legitimately be `0`, so that case is reported as `… audit resolved no auditable packages — skipping (NOT a clean result)` and degrades the run instead. Both sources check it: pip via every package carrying `skip_reason` (or an empty resolution), npm via `metadata.dependencies` resolving to zero packages — `metadata.vulnerabilities.total` alone cannot tell an empty lockfile from a clean one. A green `0` over a tree nobody looked at is the one failure mode this stage exists to prevent.
- **`npm` findings name their packages:** each is printed as `pkg (severity, DIRECT dependency|transitive) — fix: …`, under the severity histogram. `isDirect` is the triage signal — a high-severity **direct** dependency ships in the browser bundle, while a transitive dev-toolchain advisory usually does not. The counts cover dev *and* runtime deps undifferentiated (`npm audit` runs without `--omit=dev`), so they are not a prod/dev split.
- **Every network call is bounded** by `$AUDIT_TIMEOUT` (default 180s, `--kill-after=30` so a tool ignoring SIGTERM cannot outlive it) — a stalled registry degrades to a skip instead of hanging the run forever. Tune it as whole seconds or a coreutils duration (`AUDIT_TIMEOUT=30`, `30s`, `2m`). Caveats the script announces rather than hides: a malformed **or zero** value falls back to 180 with a `[WARN] invalid AUDIT_TIMEOUT` (a non-numeric value would make every call exit 125 and blame the network, and coreutils reads `timeout 0` as *no limit* — the one value that would void the bound), and on a host with no usable `timeout` the calls run **unbounded** behind a `[WARN] no usable timeout — audit calls run UNBOUNDED`. That probe happens once at startup, not inside the tool call: `warn` writes to **stdout** and the tool call is a command substitution, so warning from inside it would be captured into the JSON and turn every audit into a false "offline" skip.
- **"Timed out" and "offline" are different skip lines.** A tool killed by the bound (exit 124, or 137 after `--kill-after`) reports `… audit timed out after N — skipping (raise AUDIT_TIMEOUT if the link is slow)`, not the offline message. The distinction matters because the natural reaction to a bogus "offline" is to *lower* `AUDIT_TIMEOUT`, which would disable the audit permanently.
- **Exit codes lie, JSON doesn't:** both `pip-audit` and `npm audit` exit non-zero for "vulnerabilities found" as well as for "tool/network failure". The script distinguishes the two solely by whether the JSON parses (`--format json` / `--json`) — never re-plumb it to scrape human output or trust `$?`.
- **`pip-audit` is not in `requirements.in`:** `requirements.txt` is the pip-compile'd **runtime** lockfile that builds the API image, so an audit-only tool must not be added there (it would ship to production and need a network `pip-compile` regeneration). The nightly `audit` job installs it on top (`pip install -r requirements.txt pip-audit`); do the same in a local venv before a manual run.
- **Bump, don't mute:** resolve a real finding with a deliberate dependency bump revalidated through the normal gate (Dependabot bumps follow the same local-validation path). Never add `.trivyignore`-style suppressions, `--audit-level` softening, or a skip flag to silence the tool.
- **Operator strict run:** `bash scripts/ops/audit-deps.sh --strict` exits 1 when findings exist **or when either audit degraded** — a security check that cannot tell "clean" from "did not run" is worse than none. For deliberate checks only; a unit test (`src/tests/unit/test_audit_deps_gate.py`) locks the default advisory behaviour.
- **Scope caveat — this is dependency scanning only.** The retired CI also ran a Trivy *filesystem/base-image* scan; that coverage is still gone (`.trivyignore` remains as history). `audit-deps.sh` audits `requirements.txt` and `frontend/package-lock.json`, nothing else — container/OS-package CVEs are unscanned.
- **Stubbing for tests/offline debugging:** `PIP_AUDIT_BIN` / `NPM_BIN` override the resolved binaries (`PIP_AUDIT_BIN=/bin/false NPM_BIN=/bin/false bash scripts/ops/audit-deps.sh` reproduces the fully degraded path without a network). They are honoured in real runs too, so an override announces itself with a `[WARN] … override active` line. If you see one during a normal run, the audit is not running the tools you think it is.

## Feature docs & migrations

- **YAML `extra` shape changes:** when nesting keys (e.g. `extra.cities[].neighborhoods` replacing top-level `neighborhoods`), grep consumers beyond the scraper `__init__` — Celery helpers (`_olx_neighborhood_catalog`), seed-coverage tests, and any `extra.get("neighborhoods")` readers — or BH fan-out slugs silently vanish.
- **Live Ollama goldens** (`test_ai_quality` sentiment) are `@pytest.mark.slow` and excluded from the `fast` unit stage via `-m "not slow"`. `validate.py` runs them automatically when the diff touches AI prompts/clients; `python scripts/agent/validate.py --only ai` runs them by hand (120s timeout). Ollama unreachable is a loud **SKIPPED, not passed** warning — don't rely on the 30s unit gate.
- **Soft-reset squash trap:** never `git reset --soft origin/main` then recommit if the feature branch is behind a moved `main` while your tree is still based on an older tip — the resulting commit can **delete** sibling branches' files already on `main`. Prefer `git fetch origin main && git rebase origin/main` (or merge) then a normal fixup commit; only soft-reset onto `origin/main` when the index already contains those newer main files.
- **Soft-reset staging trap:** `git reset --soft` (to `HEAD~N` or `origin/main`) leaves **every** changed file already staged. A subsequent `git add <one-file>` is additive-only — it does **not** unstage the rest — so `git add docs/...md && git commit` silently commits everything. Run `git reset HEAD -- .` (full unstage) immediately after the soft-reset, *then* `git add` selectively per intended commit (BIN-150).
- **Squash-merge commit title:** `ship.py` titles the squash commit from the branch's `git log -1` (HEAD) and lists the branch commits in the body. If the last commit is a `docs:` fixup, the merge lands with a weak title. Prefer keeping the `feat:`/`fix:` implementation commit as HEAD (commit docs first) — don't hard-reset published history to fix a title.
- **Alembic revision IDs:** never reuse a `revision` string already on `origin/main` (BIN-82 collided with BIN-84 on `d1e2f3a4b5c6`). Before writing a migration, `git fetch origin main && git ls-tree -r --name-only origin/main alembic/versions/` and grep the proposed id. Prefer opaque random hex over sequential-looking ids.
- **Alembic multi-head race (parallel branches):** two feature branches that both set `down_revision` to the same then-HEAD produce `Multiple head revisions` once both land on `main` (BIN-118 vs BIN-121). `ship.py` merges `origin/main` into the branch before validating, so after that merge (or any manual one) run `alembic heads` (or `PYTHONPATH=src .venv/bin/alembic heads`) and ensure a **single** head — re-point your migration's `down_revision` at the new main tip if needed.
- **`EnterWorktree` unavailable to background-job sessions at repo root:** a session launched at the primary checkout root (not itself an `Agent isolation:"worktree"` subagent) gets `Cannot enter worktree: ... switching is only available to sessions whose working directory is inside a worktree` when calling `EnterWorktree` with `path` on an existing worktree — even though the tool description says this should work. Fall back to plain `cd <worktree-path>` via Bash; it behaves identically for git/validate purposes.
- **`ship.py` refuses a `bmad-loop/<run>/<story>` branch:** by design, with an explicit message. The bmad-loop **orchestrator** owns merge-back for its worktree branches — it squash-merges into `main` itself after its review pass (`.bmad-loop/policy.toml [scm]`), and shipping underneath it would bypass that review and desync the run. In a bmad-loop session, finishing = commit + green `validate.py` + end the session; the fact is also pinned in `_bmad/custom/bmad-dev-auto.toml`. A worktree's validation stamp is written to the primary checkout's `.run/validated/`, so the orchestrator's merge still carries it.
- **Dirty tree vs ship:** `ship.py` refuses a dirty working tree (and `validate.py` writes no stamp on one). Parallel agents often leave unrelated edits (ADR/scripts). Stash **only** those unrelated paths before shipping; never stash or discard your feature commits. An untracked tool-harness symlink (`.claude` or `.cursor`) that isn't gitignored also counts — remove it or confirm it's ignored.
- **Playwright query-string asserts:** `URLSearchParams` encodes spaces as `+`. When polling captured request URLs, use `decodeURIComponent(url.replace(/\+/g, ' '))` before substring checks on filter values with spaces/accents.
- **Playwright Scraper Control:** `installCommonMocks` does **not** mock `GET /platforms`. Tests that assert platform `<option>` labels must call `mockPlatforms(page)` (see `frontend/tests/e2e/helpers/apiMocks.js`) or the select stays on "Loading platforms…".

## Scrapers (`validate.py --only scrapers`)

- **Cloudflare / proxy on live dry-run (BIN-127+):** QuintoAndar remains the required live probe. Additional platforms (e.g. ZapImóveis) may soft-skip on HTTP 403/429 after QA passes — treat as environmental, not a parse regression. Fail the gate when HTTP 200 succeeds but extract/normalize yields zero listings (cassettes outdated). Prefer cassette unit tests as the offline parse lock.
- **Price-funnel bisect without working price filters:** if search pages ignore `precoMinimo`/`precoMaximo` (or equivalent), bisecting saturates into thousands of identical windows. Guard with an in-band price majority check before enqueueing halves (see `ZapImoveisScraper._price_filter_effective`).

## Cleanup / Compose

- **Nothing in the merge path prunes Docker any more.** `validate.py` leaves its ephemeral `<workspace>-test` stack up between runs (`python scripts/agent/validate.py --down` removes it); `ship.py` does no teardown or image pruning. `bash scripts/ops/docker-cleanup.sh` is an occasional operator task: it prunes stopped containers, dangling/unused feature images and build cache, keeps the primary `imoveis-*` images and third-party bases, and never touches named volumes.
- **The primary project is hook-guarded, not just prose-guarded:** `.claude/hooks/guard.py` denies any `docker compose` lifecycle command (`up|down|restart|stop|start|rm|kill|build|run|exec|…`) that is not explicitly scoped to `docker-compose.test.yml` / a `*-test*` project, plus `docker system prune`, `docker volume rm|prune` and `down -v` — in every permission mode. A denial there is the rule working, not a bug to route around: a stuck primary stack is the operator's call. Rebuilding the API image after `src/api/` changes (see below) is such an operator action.
- **Subagent worktrees are git-locked:** a session that was itself given an isolated worktree by the harness (`Agent` tool `isolation: "worktree"` / `EnterWorktree`) holds a git-level lock on it, so `git worktree remove` from elsewhere warns `could not remove worktree (uncommitted changes? use with care)` — the lock, not real uncommitted work (verify with `git status --short` inside it). Let the parent session (or a human) run `git worktree remove <path> --force && git branch -D <branch>` from the primary checkout afterwards. Two corollaries (observed BIN-141): (1) `Read` on an absolute primary-checkout path works from inside the locked subagent worktree, but `Edit`/`Write` on that same primary path is refused — edit your own worktree's copy and land it via a normal commit, or hand the change to the orchestrator as text. (2) Bash also refuses `cd <primary> && git ...` in one call — verify a merge landed with `git fetch origin main && git log origin/main` run from inside your own worktree, no cd needed.

## Domain validation hooks (scraper / AI / DB / API)

The "after you change X, run gate Y" hooks live in `CLAUDE.md` § Domain validation hooks (always-on). The incident-derived gotchas behind them are recorded here:

- **Mass scrape `0 processed / N errors` with successful HTTP:** check `AppConfig` still exposes every YAML section `tasks.scrape_listings` reads (e.g. `cfg.dedup`) and worker logs for `scrape_persist_error` / `AttributeError`. Rebuild `worker_scraper` after config/scraper fixes.
- **OLX `olx_no_listing_payload` / missing `__NEXT_DATA__`:** parse Flight (`__next_f.push`) ads; intermittent Cloudflare 403 is environmental (proxy pool), not a parse regression.
- **OLX detail URLs often omit `/venda|/aluguel`:** stamp `_olx_listing_type` from the search window and prefer path segments (not substring `venda`, which matches `venda-nova`). `locationDetails` is often the **seller/region**, not the property: run `core.olx_location` reconcile before geo allowlist; backfill with `scripts/dev/fix_olx_listings.py`.
- **Never recreate the API with bare `docker compose up`:** always `compose_cmd` / `./scripts/start.sh` / `--env-file .env.local`. Empty `API_KEY` makes SPA admin calls (`/admin/schedule`, recalculate, …) return **403 Admin API key not configured**.
- **Celery beat tasks must be in `task_routes`** for a queue workers consume: `periodic` (`worker_periodic`) for everything that is not a scrape (`scrapers`, `worker_scraper`) or GPU work (`ai`, `worker_ai`). Unrouted tasks land on default `celery` (BIN-76: empty Dashboard `/system/pipeline/history`). A periodic task routed to `scrapers` waits behind scrapes that hold both slots for hours (DW-63, Story 1.18: 11,600 messages queued, the 15-minute matcher never ran). After adding a beat entry: route it to `periodic`, wrap it in `_expiring(...)` when the next run covers a missed one (never a sender or a digest), let `test_queue_layout.py` pass, and rebuild `beat` + `worker_periodic`.
- **A test fails with `Test session blocked a Redis connection to <host>:<port>/<db>`:** the suite only lets redis-py (so also the Celery publish and the rate limiter) reach the Redis named by a `REDIS_URL` whose logical DB is not 0, which `validate.py` exports for its ephemeral stack; a raw `pytest` and the gate's unit tier reach none (`src/tests/redis_isolation.py`, Story 1.18: a raw run once published a real scrape to the primary broker). Mock the Redis client and the publish in a unit test; put a test that needs a real Redis under `src/tests/integration/` and take the URL from `tests.env_helpers.get_redis_url()`.
- **Periodic tasks not running, or `GET /system/status` says `No worker consumes queue(s): …`:** the named worker service is down or was never created (`worker_periodic` exists only after a rebuild that includes Story 1.18). Queue lengths: `GET /system/pipeline` (`queues.scrapers`, `queues.ai`, `queues.periodic`); the monitor warns `queue_monitor_periodic_backlog` above 100.
- **A scheduled scrape does not start:** look for `scrape_enqueue_skipped` in the beat log (`reason` `queued` or `running`): one scrape per platform and scope at a time. A killed scrape leaves `scrape:single_flight:<platform>:default:running:lease`, which expires by itself within two hours (the queued lease within three). A task that returns `{"status": "skipped", "reason": "already_running"}` was a duplicate delivery.
- **Properties `max_price` must filter `property_listings` by `price_type`** (`rent`|`sale`), not decisioning `p.price` (lowest listing, rent-preferred) — otherwise sale budgets match dual-listed homes on cheap rent (BIN-77). Hide number steppers on typed amount inputs (`type="text"` + `inputMode="numeric"`; CSS alone is not enough — BIN-79).
- **API image does not bind-mount `src/`:** after `src/api/` filter/route changes, `docker compose --env-file .env.local build api && docker compose --env-file .env.local up -d api` before trusting local UI against Docker (BIN-79 stale-image miss). This is a **run-the-app** concern — validation itself never rebuilds or restarts primary services.
- **Deep links use sequential `public_id` in URLs; UUID remains the PK.** Any endpoint that stores `property_id` (favourites, watchlist, …) must resolve via `api.property_refs.resolve_property_uuid` — digit-only refs are `public_id`, not UUID (BIN-82 / #85 UUID cast 500).
