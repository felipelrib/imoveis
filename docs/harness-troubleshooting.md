# Harness Troubleshooting

Accumulated gotchas from running the feature pipeline (implement → validate → docs → PR/merge). This doc exists so `.claude/skills/feature-pipeline/SKILL.md` and `.cursor/skills/feature-pipeline/SKILL.md` can stay short procedural checklists instead of growing without bound — new gotchas get appended **here**, not inlined into the steps themselves. Tool-agnostic: applies the same whether you're running Claude Code or Cursor.

When `harness-retrospect` finds a new one-off failure worth remembering, add it to the relevant section below rather than to the SKILL.md step it was found in.

## Workspace setup

- **`setup-workspace.sh` argument handling:** don't pass `--help` (or other unknown flags) — the script treats non-flag args as the branch slug and will create a real worktree (e.g. `feat/help`). Read the script header for usage; tear down accidental worktrees with `git worktree remove --force <path>` + `git branch -D`.
- **Already-isolated sessions (native product worktrees):** if the calling product already gave this session its own dedicated worktree before `setup-workspace.sh` ever ran (Claude Code's `EnterWorktree` tool / `Agent` `isolation: "worktree"`, or Cursor's background-agent dispatch), `setup-workspace.sh`/`setup-worktree.sh` detect this (`in_linked_worktree()` in `lib.sh`) and configure ports/`.env.local`/symlinks **in place** rather than creating a second, nested/sibling worktree. Creating a redundant sibling worktree in that case would try to relocate outside the product's own sanctioned worktree root — permission-gated for Claude Code (`"a model-supplied worktree outside .claude/worktrees/"`). Use `--force-branch` if you explicitly want in-place `setup-branch.sh` behavior instead.
- **Parallel worktrees:** push the new local branch (`git push -u origin HEAD`) before another agent/tool needs to fetch it from origin, if origin doesn't have it yet. Always `cd` / set `working_directory` to the **worktree** path before that push — a shell still rooted on the busy primary can push the wrong branch.
- Worktrees symlink the primary `.venv` (via `setup-worktree.sh`). If validate uses system python and fails on `pgvector`/`geoalchemy2`, create or link `.venv` before re-running.
- **`.env.local` + `API_KEY`:** `setup-worktree.sh` writes ports / `COMPOSE_PROJECT_NAME` / `PLAYWRIGHT_PORT` but does **not** copy `API_KEY`. Before `run-services.sh`, seed `API_KEY` from the primary `.env.local` (or `.env.local.example`'s `local-dev-api-key`). Without it, Compose fails with `required variable API_KEY is missing`.

## Implementation

- **Sonar Reliability (FastAPI / floats):** raise `HTTPException` only inside the decorated route (with `responses=` for each status). Helpers should raise `ValueError`/`RuntimeError` and let the route map them — Sonar fails Reliability when 400/500 are raised from shared helpers without OpenAPI docs. Avoid `score == 0.0` float equality (S1244); use falsy checks (`not score`) or integer/sentinel comparisons for "missing AI score" semantics.
- **FastAPI `Query()` models:** put all query fields on the Pydantic model. Mixing `Annotated[Model, Query()]` with extra `Query(...)` parameters (or an injected `Depends` next to the model) can make FastAPI treat the model as a required nested object (`422 Field required` on `filters_in`). Prefer `dependencies=[Depends(...)]` on the route when the handler doesn't need the dependency's return value.
- **Pydantic `BeforeValidator` + optional pattern:** don't put `Field(None, pattern=…)` inside `Annotated[..., BeforeValidator(...), Field(...)]`. That yields `TypeError: Unable to apply constraint 'pattern' to supplied value None for schema of type 'function-before'` on export/OpenAPI when the field is omitted. Use `Annotated[Optional[str], BeforeValidator(...)]` and set `Field(None, pattern=…)` on the model attribute instead (BIN-100).
- **Response models vs AI domain:** `condition_score` / `sentiment_score` (and similar AI fields) are floats — typing them as `int` causes `ResponseValidationError` → 500 on enriched rows (BIN-56). Lock with unit tests that `model_validate` projected rows with fractional scores; don't soft-pass contract 500s when the DB schema is ready.
- **Rate-limited route unit tests:** unit CI has no Redis. Bypass `slowapi.extension.Limiter._check_request_limit` (set `request.state.view_rate_limit`) when TestClient-hitting `@limiter.limit` endpoints with mocked DB.
- **`_is_unchanged` / MagicMock fixtures:** when extending `core.dedupe._is_unchanged` with new fields (`address`, `props_json`, `location`, …), update `test_dedupe_noop.py` helpers to set those attributes explicitly. Bare `MagicMock()` invents truthy stand-ins, so identical-looking fixtures fail with `assert False is True`.
- **`react-hooks/set-state-in-effect` + custom hooks (BIN-141):** the ESLint rule only recognizes a call as a "state setter" when it can trace it back to a literal `const [x, setX] = useState(...)` in the same file. If you extract state into a custom hook (e.g. `usePropertiesPagination` returning `{ page, setPage }`) and call the setter inside a `useEffect` that previously had an `eslint-disable-next-line react-hooks/set-state-in-effect` right above it, that disable comment becomes an "unused directive" warning — but the *next* statement in the effect that calls a real local `useState` setter (even indirectly, e.g. through a plain non-memoized helper like `load()`) now picks up the violation instead. Fix by moving/adding the disable comment to whichever line the rule actually flags after the extraction, not by assuming the original placement still applies.

## Validation (`validate.sh`)

- **WSL Playwright libs:** if E2E fails with `libnspr4.so: cannot open shared object file` and `sudo` is unavailable, `apt-get download` the missing libs, extract with `dpkg-deb -x`, and re-run validate with `LD_LIBRARY_PATH` pointing at the extracted `usr/lib/$(uname -m)-linux-gnu`. CI installs deps via `npx playwright install --with-deps`. On newer Ubuntu (e.g. resolute), prefer `t64` package names (`libatk1.0-0t64`, `libcups2t64`, …); non-`t64` names may have "no candidate". Cache under `/tmp/pw-libs` and export `LD_LIBRARY_PATH` for the whole `validate.sh all` / `finish-feature.sh` invocation.
- **Playwright port clash (parallel worktrees):** default E2E port is `5177` (`PLAYWRIGHT_PORT`). If validate fails with `http://localhost:5177 is already used`, export a free port (e.g. `PLAYWRIGHT_PORT=5187`) for that run, or `fuser -k 5177/tcp` if the leftover process is yours.
- **Map / MapLibre e2e:** do not unmount `MapView` (or swap it for a skeleton) while a bbox refetch sets `mapLoading` — remounts drop HTML compare hit targets and flake in CI (BIN-115). Keep the map mounted; use an overlay. For canvas layers, expose `data-testid` HTML Marker hit targets; wait for `.maplibregl-canvas` before asserting selects.
- **WSL `DATABASE_URL`:** unset a stale host `DATABASE_URL` before `validate.sh` so `.env.local`'s `POSTGRES_PORT` can derive the compose DB URL. A leftover `localhost:5432` often hits a non-compose Postgres and fails auth. Host pytest always uses the isolated `realestate_test` (see `ensure-test-db.sh`); Compose scrapers keep `realestate`.
- **Host pytest Redis DB:** `validate.sh` forces `REDIS_URL` to logical DB `REDIS_TEST_DB` (default **15**). Compose API/Celery keep DB **0**. Integration `flushdb` fixtures refuse DB 0 unless `IMOVEIS_ALLOW_PRIMARY_REDIS_WIPE=1` (BIN-117).
- **Alembic vs fresh Postgres race:** `validate.sh all` can set `rc=1` when compose `alembic upgrade head` hits `FATAL: the database system is starting up` even after a healthy check — later ensure-test-db/contract/e2e may still pass. Re-run validate (or the compose alembic upgrade alone) once Postgres is fully up; don't treat that transient as a product regression.
- **Playwright checkbox limits:** when UI intentionally blocks checking (e.g. max-4 select), use `locator.click()` not `locator.check()` — `.check()` fails if the controlled input doesn't become checked.
- **Playwright AI / closed-vocab labels:** after risk flags and category codes go through `t()` / `labelRiskFlag`, assert catalog display strings (`Flood zone`, `Slightly Undervalued`), not raw codes (`flood`, `slightly_undervalued`). Playwright `toContainText('flood')` does **not** match `Flood` (BIN-101+).
- **Playwright strict mode / shared labels:** when card chrome starts showing the same strings as filters (e.g. city in `📍 Neighborhood, City`), scope assertions to the control under test (`getByTestId('…-dropdown').getByText(…)`) — bare `getByText('Belo Horizonte')` will match the card and fail strict mode. Same trap when a fixture **title** contains badge/copy under test (BIN-114: title "Bundled Fees…" vs badge "Bundled fees") — assert via `getByTestId('listings-by-platform').getByText(…)` (or rename the fixture title). Also toast vs activity-log: if the toast string is a substring of a log line (BIN-123: "Availability recheck enqueued"), use `getByText(…, { exact: true })` or scope to the toast container — otherwise strict mode matches both.
- **Playwright boot-time admin GETs:** if the SPA calls a new `/admin/*` endpoint on App mount (e.g. locale preference), add a default mock inside `installCommonMocks` (or a shared helper invoked from it). Otherwise suites that seed `sessionStorage` API keys emit Vite `ECONNREFUSED` proxy noise against the worktree API port even when tests still pass.
- **i18n catalog migrations:** keep default-locale (`en`) catalog values byte-identical to existing Playwright `getByText` / role-name asserts — don't "improve" EN copy while migrating. When number/date helpers switch from hardcoded `pt-BR` to the active locale, update e2e digit-grouping asserts (`3.000` → `3,000`) for the default `en` suite; add a separate PT smoke spec for translated chrome (BIN-99+).
- **Add a third locale:** follow [`docs/i18n/add-a-locale.md`](i18n/add-a-locale.md) (catalog → allowlist → synonym maps → AI template **dicts** → semantic lexicon → tests). Prefer `localeLabelKey` / template registries over `if locale ==` / switcher ternaries — `test_locale_registry_hygiene.py` spot-checks the latter.

## Feature docs & migrations

- **YAML `extra` shape changes:** when nesting keys (e.g. `extra.cities[].neighborhoods` replacing top-level `neighborhoods`), grep consumers beyond the scraper `__init__` — Celery helpers (`_olx_neighborhood_catalog`), seed-coverage tests, and any `extra.get("neighborhoods")` readers — or BH fan-out slugs silently vanish.
- **Live Ollama goldens** (`test_ai_quality` sentiment) are `@pytest.mark.slow` and excluded from `validate.sh` / CI unit via `-m "not slow"`. Run them with `bash scripts/agent/validate-ai.sh` (120s timeout) after prompt/client changes — don't rely on the 30s unit gate.
- **Lint trap:** `validate.sh` isort only covers `src/`; CI `pre-commit` also sorts `alembic/versions/` and `scripts/`. Run `pre-commit run isort --all-files` (or at least isort on touched alembic/scripts paths) before push when adding migrations or `scripts/dev/` tooling. Single-line HTML cassettes under `src/tests/fixtures/` must end with a trailing newline (`end-of-file-fixer`) or the lint job fails while flake8 is green.
- **Soft-reset squash trap:** never `git reset --soft origin/main` then recommit if the feature branch is behind a moved `main` while your tree is still based on an older tip — the resulting commit can **delete** sibling PRs' files already on `main`. Prefer `git fetch origin main && git rebase origin/main` (or merge) then a normal fixup commit; only soft-reset onto `origin/main` when the index already contains those newer main files.
- **Alembic revision IDs:** never reuse a `revision` string already on `origin/main` (BIN-82 collided with BIN-84 on `d1e2f3a4b5c6`). Before writing a migration, `git fetch origin main && git ls-tree -r --name-only origin/main alembic/versions/` and grep the proposed id. Prefer opaque random hex over sequential-looking ids.
- **Alembic multi-head race (parallel PRs):** two feature branches that both set `down_revision` to the same then-HEAD produce `Multiple head revisions` on CI once both land in the PR tree (BIN-118 vs BIN-121). Before push / after merging `origin/main` into the feature branch, run `alembic heads` (or `PYTHONPATH=src .venv/bin/alembic heads`) and ensure a **single** head — re-point your migration's `down_revision` at the new main tip if needed.
- **Dirty tree vs finish:** `finish-feature.sh` refuses a dirty working tree. Parallel agents often leave unrelated edits (ADR/scripts). Stash **only** those unrelated paths before finish; never stash or discard your feature commits. A parallel `setup-worktree.sh` run may also leave an untracked tool-harness symlink (`.claude` or `.cursor`) if it isn't gitignored in that checkout — remove it or confirm it's ignored before `finish-feature.sh`, since porcelain dirtiness blocks finish.
- **Playwright query-string asserts:** `URLSearchParams` encodes spaces as `+`. When polling captured request URLs, use `decodeURIComponent(url.replace(/\+/g, ' '))` before substring checks on filter values with spaces/accents.
- **Playwright Scraper Control:** `installCommonMocks` does **not** mock `GET /platforms`. Tests that assert platform `<option>` labels must call `mockPlatforms(page)` (see `frontend/tests/e2e/helpers/apiMocks.js`) or the select stays on "Loading platforms…".

## Scrapers (`validate-scrapers.sh`)

- **Cloudflare / proxy on live dry-run (BIN-127+):** QuintoAndar remains the required live probe. Additional platforms (e.g. ZapImóveis) may soft-skip on HTTP 403/429 after QA passes — treat as environmental, not a parse regression. Fail the gate when HTTP 200 succeeds but extract/normalize yields zero listings (cassettes outdated). Prefer cassette unit tests as the offline parse lock.
- **Price-funnel bisect without working price filters:** if search pages ignore `precoMinimo`/`precoMaximo` (or equivalent), bisecting saturates into thousands of identical windows. Guard with an in-band price majority check before enqueueing halves (see `ZapImoveisScraper._price_filter_effective`).

## Cleanup / Compose

- **Stale worktree env in the shell:** after `teardown.sh --remove` (or after sourcing a worktree `.env.local`), `unset COMPOSE_PROJECT_NAME POSTGRES_PORT REDIS_PORT API_PORT FRONTEND_PORT PLAYWRIGHT_PORT` before running `docker compose` on the primary — otherwise Compose recreates `feat-*` projects against busy ports and can look like the primary stack vanished.
- Never run `teardown.sh --remove` from the primary checkout expecting worktree removal — run it from the worktree (or pass the worktree path explicitly). Primary teardown only stops the primary Compose project.
- **`finish-feature.sh --pr` teardown can't remove its own subagent worktree:** when running inside a session that was itself given an isolated worktree by the harness (`Agent` tool `isolation: "worktree"` / `EnterWorktree`), the worktree is `locked` at the git level for that session. `finish-feature.sh`'s `teardown.sh --remove` step still stops/removes Compose containers, volumes, and local images correctly, but the final `git worktree remove` warns `could not remove worktree (uncommitted changes? use with care)` and leaves the directory + branch on disk — this is the lock, not actual uncommitted work (verify with `git status --short` inside the worktree). `ExitWorktree` also refuses from inside that same subagent (`cannot be called from a subagent with a cwd override — it would mutate the parent session's working directory`). There is no in-session fix: after confirming the PR merged and the tree is clean, report the leftover path/branch in the wrap-up and let the parent/orchestrating session (or a human) run `git worktree remove <path> --force && git branch -D <branch>` from the primary checkout. Two more corollaries (observed BIN-141): (1) `Read` on an absolute primary-checkout path works fine from inside the locked subagent worktree, but `Edit`/`Write` on that same primary path is refused ("Edit the worktree copy of this file instead") — so `harness-retrospect`'s "always edit the primary checkout" instruction doesn't apply here; either edit your own worktree's copy and land it via a normal small commit/PR, or hand the change to the orchestrator as text. (2) Bash also refuses `cd <primary> && git ...` in one call ("a worktree-isolated agent's git operations must target its own worktree") — verify a merge landed with `git fetch origin main && git log origin/main` run from inside your own worktree, no cd needed.

## PR / CI

- If `gh pr checks` stays empty after push (no `pull_request` workflow run), recreate the PR (`gh pr close` → `gh pr create`). Empty-commit nudges and `workflow_dispatch` alone may not attach required checks to the PR.
- `finish-feature.sh --pr` may exit with a CI timeout warning while checks are still **queued** — that is not a failure. Continue with babysit (`gh pr checks --watch`) until green, then merge.
- **`check-json` pre-commit hook rejects JSONC comments:** CI's `lint` job runs `pre-commit run --all-files`, which includes `check-json` (strict `json.load`, no `/* */` or `//` comments) — `validate.sh` does **not** run this locally, so a JSON file with comments (e.g. a hand-authored `tsconfig.json` using the conventional `/* rationale */` comment style TS itself tolerates) passes every local gate and only fails in CI. Keep `.json` files (including `tsconfig.json`) comment-free; put rationale in the feature doc or a `// eslint-disable`-style adjacent code comment in a `.js`/`.ts` file instead. Sanity-check before push: `python3 -c "import json; json.load(open('path/to/file.json'))"`.
