# ADR 0005 — Drop Linear; BMad artifacts become the sole tracker

- **Status:** accepted (2026-08-05) — amends ADR 0002/0003 where they name Linear as the execution tracker
- **Context:** Linear (team Bino) had been the execution tracker and, after the 2026-08-05 BMad-SoR pivot, the *tracking mirror* for BMad planning. On 2026-08-05, mid-sync of the v0.13 epics, the workspace hit Linear's free-plan issue limit (issue creation rejected). Rather than paying for or pruning a mirror, the decision (Felipe, 2026-08-05) is to drop Linear entirely.

## Decision

1. **Plan of record:** `_bmad-output/planning-artifacts/epics.md` (epics + stories + acceptance criteria + FR coverage). Milestones remain versioned (`v0.N`) and live in the epics doc frontmatter/PRD — no external milestone objects.
2. **Execution status:** `_bmad-output/implementation-artifacts/sprint-status.yaml` (generated by `bmad-sprint-planning`, updated as stories progress; statuses only move forward). This file replaces Linear issue states (Backlog / In Progress / Done).
3. **Story keys** replace `BIN-<id>` everywhere forward-looking: `v<milestone>-s<epic>.<story>` (e.g. `v0.13-s1.1`), as written in epics.md / sprint-status.yaml. Follow-ups without a story get `v<milestone>-fu<N>` keys minted in sprint-status.yaml (replacing "create a placeholder Linear issue").
4. **Feature docs:** `docs/features/<story-key>-<slug>.md` (e.g. `v0.13-s1.1-task-class-routing.md`). Unique by construction — parallel PRs cannot collide. Legacy `BIN-*`-prefixed docs are history and keep their names.
5. **Branches:** include the story key when working a story (e.g. `feat/v0.13-s1.1-task-class-routing`) so `gen-docs.sh` can derive the doc name; plain slugs stay fine for non-story work.
6. **Epic completion:** the close gate survives, re-targeted — an epic is closed by checking sprint-status.yaml + epics.md + `docs/features/` follow-ups (see `.claude/skills/epic-completion/SKILL.md`), and recorded as `epic-N: done` in sprint-status.yaml.
7. **Deferred/abandoned Linear state:** milestones v0.1–v0.12 and all `BIN-*` issues remain in Linear as a read-only historical archive. The partially synced v0.13 artifacts (milestone + BIN-273/274/275) were canceled/marked abandoned on 2026-08-05. Historical `BIN-<id>` references in docs, commit messages, and incident notes stay — they are real history.

## Consequences

- The Linear MCP server is no longer required by any workflow; harness instructions must not tell agents to update Linear. (The connector may stay configured for reading the archive.)
- `imoveis-planning-bridge` no longer syncs epics/stories anywhere — epics.md *is* the backlog. The mandatory **Parallel work plan** after epic refinement survives, using story keys instead of BIN links.
- The PRD 2026-08-05 §0 statement "Linear remains the tracking mirror" is superseded by this ADR; fold into the PRD text at its next update.
- Single point of loss: tracking now lives entirely in git — acceptable, since the repo already is the system of record and Linear was write-mostly.
